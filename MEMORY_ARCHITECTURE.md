## PART I — THE NATURE OF MEMORY

*What memory is, why it is categorically distinct from all adjacent concepts, what it commits the intelligence system to, and why memory architecture is the foundational discipline upon which all other intelligence capabilities depend.*

---

### 1 — What Is Memory?

Memory is the **active, contextualized, decaying-and-reinforcing, integrating record of everything intelligence has encountered, processed, decided, and learned — made permanently accessible for future reasoning, decision-making, and further learning.**

Memory is not data storage. Data storage holds numbers and strings without context, without decay, without reinforcement, and without the associative web that gives memory its power. Memory holds meaning — the lived, attributed, contextualized record of experience that can be retrieved, recognized, and reapplied when the conditions that originally produced it are encountered again.

Four essential properties distinguish genuine memory from all forms of mere storage:

**Accessibility** — Memory is a live, active resource, not a static archive. It exists to be retrieved at the moment it is needed, in the context where it is needed, at the speed demanded by the intelligence cycle. Data sitting in a file system that is never queried is not memory — it is storage. A fact that cannot be recalled when the reasoning system needs it has no memory value regardless of whether it is technically stored. Memory accessibility means the system can reach the right memory at the right time in response to the right cue.

**Contextualization** — Memory does not store facts in isolation. It stores facts embedded in the full context of their creation: when they were observed, what market regime was active, what reasoning chain was engaged, what decision was made, what outcome followed, what was learned. This context is not metadata — it is the substance of the memory. The same price movement means something fundamentally different in a trending bull market versus a collapsing bear market. Memory without context is a decontextualized data point; memory with context is actionable intelligence.

**Decay and Reinforcement** — Genuine memory is dynamic. It strengthens with repeated successful retrieval and use (reinforcement) and weakens with disuse, contradicting evidence, and the passage of time through changed conditions (decay). A memory system that neither decays nor reinforces is not a memory system — it is a database. The decay-reinforcement architecture is what determines which knowledge stays fresh and actively influential, which recedes to archive status, and which is intentionally forgotten. Without decay, a memory system eventually becomes a museum of outdated information that cannot be distinguished from current relevant knowledge.

**Integration** — Memory does not consist of isolated records. Memories are linked to each other through associations, temporal sequences, causal relationships, structural similarities, and contextual overlaps. When one memory is retrieved, its entire network of associations is partially activated — enabling rich, contextual, associative reasoning that cannot be achieved by isolated data lookup. A trade outcome memory activates related pattern memories, which activate related strategy memories, which activate related regime memories. This web of associations is the mechanism by which intelligence is richer than mere data retrieval.

**Memory is not:**
- Storage — organized persistence without accessibility, context, decay, or integration
- Archive — organized storage without active retrieval or reinforcement
- Database — structured storage without decay, associative linking, or contextual embedding
- History — a record of past events without contextual linking or active influence on current reasoning
- Knowledge — the structured understanding derived from memory, not the memory itself
- Learning — the process of creating and updating memory records, not the memory records themselves
- Experience — the raw events that memory is created from, not the resulting memory records
- Data — the numerical or categorical substrate of information, not the contextualized, integrated record
- Information — structured data, not the contextualized, persistent, actionable memory record
- Recall — the process of retrieving a memory, not the memory itself

**Memory is** the permanent, contextual, integrated, decaying-and-reinforcing record of all that intelligence has encountered, reasoned through, decided, and learned — the substrate from which all future reasoning, all future decisions, and all future learning draws its raw material. Without memory, intelligence is momentary. With memory, intelligence is cumulative.

### 3 — Why Memory Exists

Memory exists for five fundamental reasons, each of which is a structural requirement for investment intelligence:

**Reason 1 — Pattern Recognition Across Time:** A system without memory can only recognize patterns it encounters in the current observation. A system with memory can recognize that the current pattern has occurred before, what conditions surrounded it then, and what outcome followed. The longer and richer the memory, the more powerful the pattern recognition. Memory is the engine of experiential learning — without it, every situation is novel regardless of how many times it has been seen.

**Reason 2 — Decision Quality:** Every high-quality investment decision is informed by experience — by what has worked before, what has failed, what conditions are similar to prior successful setups, and what risks have emerged in similar situations. This experience can only be accessed if it is remembered. A decision-making system without memory must rely entirely on current data and hard-coded rules — losing all the accumulated wisdom that makes experience valuable.

**Reason 3 — Learning Continuity:** Learning produces lessons — modifications to knowledge, evidence weights, and confidence calibration. These modifications must be stored so they can influence future reasoning and decisions. Without memory, learning events produce no lasting change — the system reverts to its prior state at the next cycle. Memory is the medium in which learning persists.

**Reason 4 — Institutional Continuity:** A system that restarts from scratch with each session has no institutional continuity — it cannot build on prior work, cannot avoid previous mistakes, and cannot develop the expertise that requires extended experience. Memory provides the institutional continuity that allows intelligence to compound over time. A trading system with five years of market memory is qualitatively different from one with five days — not because the rules are different but because the memory base is incomparably richer.

**Reason 5 — Attribution and Accountability:** Every decision made by the Investment Intelligence Operating System must be traceable to its reasoning, its evidence, and its outcome. This traceability requires memory — the stored record of what was known, what was decided, why it was decided, and what resulted. Memory is the foundation of accountability: without it, the system cannot learn from the past because the past is invisible.

### 5 — Why Intelligence Cannot Exist Without Memory

Intelligence is the ability to perceive, reason, decide, and learn effectively across time and context. Every one of these four capabilities requires memory:

**Perception requires memory** because recognizing the significance of what is currently observed requires comparison to what has been observed before. A price move that is "significant" is only significant relative to a historical distribution of price moves. The current order flow is only "unusual" against remembered normal order flow. Without memory, perception is blind to historical context.

**Reasoning requires memory** because reasoning draws on principles, patterns, causal relationships, and beliefs that must have been learned and stored. A reasoning system that has no access to prior outcomes, prior errors, and prior validated patterns must reason from first principles alone — producing generic conclusions where specific, experience-grounded conclusions are possible and superior.

**Decision-making requires memory** because every non-trivial investment decision draws on accumulated experience. The entry decision asks: "Have I seen this setup before? What happened?" The exit decision asks: "Have I held a position through similar price action before? What did I learn?" The sizing decision asks: "What conviction scores led to correct decisions in the past?" Without memory to answer these questions, decisions are blind.

**Learning requires memory** because learning events modify knowledge, and those modifications must be stored as memory to influence future cycles. Learning without memory is change without persistence — the system improves for one cycle and then forgets its improvement.

An intelligence system without memory is not merely a less capable intelligence — it is not an intelligence system at all. It is a reactive system: it perceives the current state, produces a response, and returns to zero. Every capability that makes investment intelligence superior to simple rules — pattern recognition, calibration, institutional knowledge, expertise — requires memory.

## PART III — THE 25 MEMORY PRIMITIVES

### The Purpose of Primitives

Vocabulary names what memory is. Primitives define what memory *does* at its most fundamental level.

A memory primitive is not a concept — it is an atomic unit of memory operation. Where vocabulary concepts answer "what does this mean?", primitives answer "what exactly happens?". Each primitive is defined with 28 precise attributes covering identity, lifecycle, quality, governance, and failure — giving the system architect everything needed to instantiate, manage, and audit any memory operation.

The 25 memory primitives cover the full operational spectrum:
- **Storage primitives** — how memory records are created and held
- **Process primitives** — how memories move through their lifecycle
- **Event primitives** — what triggers memory operations
- **State primitives** — what configurations memory can be in
- **Reference primitives** — how memories link to other structures

### MPRIM-001: Memory Record

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-001 |
| **Primitive Name** | Memory Record |
| **Primitive Class** | Storage |
| **Definition** | The atomic unit of storage in the memory system — a self-contained record capturing one experience, decision, outcome, or lesson with full contextual embedding |
| **Purpose** | To give the intelligence a persistent, retrievable, and contextualized representation of everything it has encountered — the fundamental building block of all memory |
| **Memory Tier** | All tiers — created in working memory, may persist through short-term, long-term, and institutional tiers |
| **Creation Event** | Triggered by any of: trade execution, outcome observation, learning event, market event, governance decision, or explicit lesson extraction |
| **Creation Authority** | Any layer may create a Memory Record — Layer 17 ControlTower registers and indexes all records |
| **Mandatory Fields** | record_id, record_type, content, creation_time, event_time, source_layer, strength, confidence |
| **Optional Fields** | regime_context, strategy_id, instrument_id, outcome, lesson, attribution, version, associations |
| **Strength Range** | 0.0–1.0 — creation default: 0.5 for inferred records; 0.8 for observed records; 1.0 for governance records |
| **Confidence Range** | 0.0–1.0 — creation default: matches source layer's confidence in the event |
| **Decay Model** | Exponential by default — decay rate calibrated by record_type; high-value lessons decay at 0.001/day; routine observations at 0.05/day |
| **Reinforcement Model** | Each successful retrieval for a verified decision increases strength by 0.05; correct outcome prediction increases by 0.1 |
| **Consolidation Criteria** | Strength ≥ 0.7 AND age ≥ 1 cycle AND at least one successful retrieval |
| **Retrieval Cues** | record_type, entity, regime, time range, strength threshold, content keyword |
| **Association Types** | Temporal (same session), causal (outcome links), structural (similar records), entity (same instrument) |
| **Update Policy** | Field-level updates permitted — each update creates a new version; original preserved |
| **Version Policy** | All versions retained; current version tagged; rollback to any prior version available |
| **Archival Criteria** | Strength < 0.2 AND age > 90 days AND no retrieval in 30 days |
| **Deletion Criteria** | Archive age > 365 days AND record_type ≠ GOVERNANCE AND no preservation order |
| **Audit Frequency** | Weekly quality review; monthly compliance review |
| **Quality Gate** | strength ≥ 0.3 AND confidence ≥ 0.3 AND all mandatory fields populated |
| **Failure Modes** | Missing context (creates blind recall), strength inflation (retrieves irrelevant records), timestamp error (temporal reasoning fails) |
| **Related Primitives** | MPRIM-002 (Episode contains Records), MPRIM-004 (Cluster groups Records), MPRIM-005 (Index references Records) |
| **Layer Owner** | Layer 17: ControlTower |
| **Cross-Layer Use** | All 17 layers read; Layers 10, 13, 14 write most frequently |
| **Constitutional Constraints** | Principles M-001 (Complete Context), M-002 (Immutable History), M-015 (Attribution Required) |

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-002 |
| **Primitive Name** | Memory Episode |
| **Primitive Class** | Storage |
| **Definition** | A structured collection of Memory Records (MPRIM-001) that together describe a complete experiential event — a trade lifecycle, a market crisis, a strategy failure, or a learning breakthrough |
| **Purpose** | To preserve the narrative coherence of complex experiences — ensuring that individual facts are not recalled in isolation but as part of the episode that gave them meaning |
| **Memory Tier** | Long-term — Episodes survive beyond single sessions; institutional episodes persist permanently |
| **Creation Event** | Triggered by: trade closure (trade episode), session end (session episode), regime transition (regime episode), or learning consolidation (learning episode) |
| **Creation Authority** | Layer 13: LearningSystem — primary; Layer 12: TradeMonitoring — for trade episodes |
| **Mandatory Fields** | episode_id, episode_type, start_time, end_time, constituent_records[], summary, outcome, lessons[] |
| **Optional Fields** | regime_context, strategy_ids[], instruments[], conviction_scores[], risk_metrics, attribution |
| **Strength Range** | 0.0–1.0 — creation default: 0.6; scales with outcome significance |
| **Confidence Range** | 0.0–1.0 — reflects attribution confidence; defaults to minimum of constituent record confidences |
| **Decay Model** | Stepped decay — loses 0.05 strength per quarter without retrieval; significant episodes (abs outcome > 2 sigma) decay at half rate |
| **Reinforcement Model** | Retrieved episode gains 0.08 strength; episode used in successful analogue reasoning gains 0.15 |
| **Consolidation Criteria** | All constituent records consolidated AND episode reviewed by LearningSystem AND lesson_count ≥ 1 |
| **Retrieval Cues** | episode_type, date range, regime, strategy, instrument, outcome direction, magnitude threshold |
| **Association Types** | Temporal (sequential episodes), causal (one episode caused another), analogical (similar episode structure), regime (same regime episodes) |
| **Update Policy** | Post-closure episodes may be annotated (lessons updated, attribution refined) but core records are immutable |
| **Version Policy** | Episode summaries are versioned; constituent records maintain their own versioning |
| **Archival Criteria** | Strength < 0.15 AND age > 180 days AND episode_type ≠ CRISIS AND episode_type ≠ INSTITUTIONAL |
| **Deletion Criteria** | Archive age > 730 days AND no lesson references active |
| **Audit Frequency** | Monthly episode review; quarterly comprehensive episode audit |
| **Quality Gate** | All mandatory fields populated AND constituent_records count ≥ 1 AND summary is non-empty |
| **Failure Modes** | Episode boundary error (records from different episodes merged), incomplete episode (closure without all records), narrative loss (summary loses key context) |
| **Related Primitives** | MPRIM-001 (constituent records), MPRIM-003 (Traces feed Episodes), MPRIM-017 (Episodic Memory Entry built from Episodes) |
| **Layer Owner** | Layer 13: LearningSystem |
| **Cross-Layer Use** | Layer 5 (StrategyLab), Layer 10 (DebateAndDecision), Layer 14 (PerformanceAnalytics), Layer 15 (ResearchLab) |
| **Constitutional Constraints** | Principles M-003 (Narrative Integrity), M-004 (Complete Episodes), M-015 (Attribution Required) |

### MPRIM-003: Memory Trace

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-003 |
| **Primitive Name** | Memory Trace |
| **Primitive Class** | Storage |
| **Definition** | A lightweight, incomplete memory record representing the initial impression of an event — created immediately at event time before full context is available; refined or promoted to full Memory Record upon completion |
| **Purpose** | To ensure no event is lost by capturing the minimum viable record immediately, before full processing completes — prevents the common failure of losing an event's initial conditions to latency |
| **Memory Tier** | Short-term — Traces are transient; they either mature into Memory Records or are discarded |
| **Creation Event** | Triggered at the instant any significant event begins: order submitted, market signal detected, news event received |
| **Creation Authority** | Any layer detecting an event — typically Layers 2, 6, 11, 12 |
| **Mandatory Fields** | trace_id, source_event_type, detection_time, source_layer, initial_observation |
| **Optional Fields** | preliminary_strength, parent_episode_id, instrument_id, regime_snapshot |
| **Strength Range** | 0.0–1.0 — creation default: 0.3 (transient); not subject to reinforcement until promoted |
| **Confidence Range** | 0.0–1.0 — typically 0.3–0.5 at creation; reflects incomplete information |
| **Decay Model** | Rapid decay — 0.1 per cycle if not promoted; fully expired if not promoted within 24 hours |
| **Reinforcement Model** | Not subject to direct reinforcement — promotion to Memory Record provides the upgrade |
| **Consolidation Criteria** | Does not consolidate — either promoted to Memory Record or discarded |
| **Retrieval Cues** | trace_id, source_event_type, time range — Traces are rarely retrieved directly |
| **Association Types** | Parent episode link only at creation stage |
| **Update Policy** | May be refined with additional fields during its active lifecycle before promotion |
| **Version Policy** | No versioning — Traces are point-in-time snapshots, promoted or discarded whole |
| **Archival Criteria** | Not archived — discarded upon expiry |
| **Deletion Criteria** | Age > 24 hours without promotion, OR promotion completed (replaced by full Memory Record) |
| **Audit Frequency** | Real-time monitoring for promotion backlog |
| **Quality Gate** | Mandatory fields populated — no strength or confidence gate at Trace level |
| **Failure Modes** | Trace expiry before promotion (event lost), Trace promotion delay (context staleness), Trace duplication (same event traced twice) |
| **Related Primitives** | MPRIM-001 (Trace promotes to Record), MPRIM-002 (Trace feeds Episode), MPRIM-010 (Recall Event may trigger Trace review) |
| **Layer Owner** | Layer 12: TradeMonitoring |
| **Cross-Layer Use** | Layer 11 (ExecutionEngine), Layer 6 (CapitalRiskEngine), Layer 2 (MarketIntelligence) |
| **Constitutional Constraints** | Principles M-006 (No Lost Events), M-007 (Temporal Accuracy) |

### MPRIM-004: Memory Cluster

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-004 |
| **Primitive Name** | Memory Cluster |
| **Primitive Class** | Storage |
| **Definition** | A named, structured group of related Memory Records and Episodes that share a common organizing principle — regime, strategy, instrument, temporal period, or thematic pattern |
| **Purpose** | To enable efficient bulk retrieval of topically related memories — rather than retrieving individual records, the system retrieves entire clusters relevant to a decision context |
| **Memory Tier** | Long-term — Clusters persist as long as their constituent memories are active |
| **Creation Event** | Triggered by: sufficient memory volume in a domain (count > 20), regime transition, strategy launch, or explicit clustering event during learning consolidation |
| **Creation Authority** | Layer 17: ControlTower — cluster assignment; Layer 13: LearningSystem — learning clusters |
| **Mandatory Fields** | cluster_id, cluster_type, organizing_principle, member_record_ids[], creation_time, cohesion_score |
| **Optional Fields** | regime_context, strategy_id, instrument_id, cluster_summary, representative_records[], expiry_condition |
| **Strength Range** | 0.0–1.0 — cluster strength is the weighted average of member record strengths |
| **Confidence Range** | 0.0–1.0 — cluster confidence is the weighted average of member confidences |
| **Decay Model** | Indirect — Cluster strength decays as member strengths decay; cluster is reviewed when aggregate strength drops below 0.3 |
| **Reinforcement Model** | Cluster activation (retrieval in bulk) increases all member strengths by 0.02; representative records gain additional 0.03 |
| **Consolidation Criteria** | cohesion_score ≥ 0.6 AND member_count ≥ 10 AND organizing_principle verified |
| **Retrieval Cues** | cluster_type, organizing_principle value, regime, strategy, instrument, time range |
| **Association Types** | Inter-cluster links (clusters share organizing principles), temporal bridges (overlapping time period clusters) |
| **Update Policy** | Members are added and removed dynamically; organizing principle and cluster_id are immutable |
| **Version Policy** | Cluster membership versioned; snapshots at each consolidation cycle |
| **Archival Criteria** | Average member strength < 0.2 AND no new members added in 90 days |
| **Deletion Criteria** | Archive age > 365 days AND no active member references |
| **Audit Frequency** | Monthly cohesion assessment; quarterly cluster review |
| **Quality Gate** | cohesion_score ≥ 0.4 AND member_count ≥ 3 |
| **Failure Modes** | Cluster pollution (dissimilar records added), cluster explosion (too many members, retrieval degrades), cluster isolation (cluster not linked to wider network) |
| **Related Primitives** | MPRIM-001 (Records are cluster members), MPRIM-005 (Index references Clusters), MPRIM-007 (Links connect Clusters) |
| **Layer Owner** | Layer 17: ControlTower |
| **Cross-Layer Use** | Layer 3 (MetaLearning), Layer 5 (StrategyLab), Layer 10 (DebateAndDecision), Layer 14 (PerformanceAnalytics) |
| **Constitutional Constraints** | Principles M-008 (Cluster Coherence), M-009 (Representative Coverage) |

### MPRIM-005: Memory Index

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-005 |
| **Primitive Name** | Memory Index |
| **Primitive Class** | Reference |
| **Definition** | A searchable catalogue structure that maps retrieval cues to memory records and clusters — enabling fast, efficient location of relevant memories without full-network traversal |
| **Purpose** | Without an index, every retrieval requires scanning the entire memory network. The Index provides direct lookup by key — reducing retrieval latency from linear to logarithmic and enabling the decision pipeline's tight timing constraints to be met |
| **Memory Tier** | All tiers — each tier maintains its own index; a master index spans all tiers |
| **Creation Event** | Created at system initialization; updated at every memory creation, modification, or deletion event |

| **Optional Fields** | tier_scope, refresh_frequency, coverage_metrics, priority_weights |
| **Strength Range** | Not applicable — Index records do not have strength (they are references) |
| **Confidence Range** | 0.0–1.0 — index confidence reflects the proportion of records correctly catalogued |
| **Decay Model** | Does not decay — Index freshness is maintained through continuous update; stale index entries are invalidated |
| **Reinforcement Model** | Not applicable — Index accuracy improves through continuous validation |
| **Consolidation Criteria** | Achieved at creation — an Index is always long-term |
| **Retrieval Cues** | index_type, index_domain — the Index is looked up by specifying what type of index is needed |
| **Association Types** | None — the Index is a reference structure, not a memory record |
| **Update Policy** | Continuous update at every memory operation — not versioned; always current |
| **Version Policy** | Index snapshots taken at consolidation cycle for recovery purposes |
| **Archival Criteria** | Never archived while live records exist in its domain |
| **Deletion Criteria** | All referenced records deleted AND domain decommissioned |
| **Audit Frequency** | Daily integrity check; weekly coverage assessment |
| **Quality Gate** | coverage_ratio ≥ 0.95 AND integrity_hash valid |
| **Failure Modes** | Index staleness (new records not indexed), index corruption (lookup leads to wrong record), index explosion (too large for fast lookup), index gap (domain not covered) |
| **Related Primitives** | MPRIM-001 (Records are indexed), MPRIM-004 (Clusters are indexed), MPRIM-009 (Retrieval Request queries Index) |
| **Layer Owner** | Layer 17: ControlTower |
| **Cross-Layer Use** | All 17 layers query the Index for memory retrieval |
| **Constitutional Constraints** | Principles M-010 (Index Completeness), M-011 (Retrieval Speed) |

### MPRIM-006: Memory Context

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-006 |
| **Primitive Name** | Memory Context |
| **Primitive Class** | Storage |
| **Definition** | A structured record of the full environmental conditions at the moment a memory was created — the contextual wrapper that transforms a bare fact into a retrievable, comparable, and applicable memory |
| **Purpose** | Context is what makes memory useful. Without context, a record that "TATASTEEL fell 3% on this date" is a data point. With context — market regime, sector conditions, FII flow, options data, prior day performance, global signals — it becomes a memory that can be meaningfully retrieved when a similar situation arises. Context is the essential distinguishing property that separates memory from storage |
| **Memory Tier** | All tiers — Context is created alongside every memory record; inherits the tier of its parent record |
| **Creation Event** | Created simultaneously with its parent Memory Record — context is captured at event time, not retrospectively |
| **Creation Authority** | Layer 2: MarketIntelligence — market context; Layer 1: GlobalIntelligence — global context; Layer 7: RiskControl — risk context |
| **Mandatory Fields** | context_id, parent_record_id, timestamp, regime, market_phase, instrument_conditions, strategy_state |
| **Optional Fields** | global_context, sector_context, macro_context, volatility_regime, liquidity_state, fii_flow, sentiment, calendar_context, policy_context |
| **Strength Range** | Not independently rated — inherits parent Memory Record's strength |
| **Confidence Range** | 0.0–1.0 — reflects accuracy of context capture; high confidence when all context sources available |
| **Decay Model** | Context does not decay independently — remains permanently associated with its parent record |
| **Reinforcement Model** | Context match quality contributes to retrieval scoring — high-quality context enables precise analogical retrieval |
| **Consolidation Criteria** | Consolidated with parent record — shares parent's consolidation event |
| **Retrieval Cues** | Context is the primary retrieval cue for analogical retrieval — current context matched against stored contexts |
| **Association Types** | Regime association (same regime contexts linked), temporal association (sequential contexts linked), instrument association (same instrument contexts linked) |
| **Update Policy** | Context is immutable after parent record creation — may only be annotated with retrospective observations |
| **Version Policy** | Single version — context captures a moment in time, cannot be revised |
| **Archival Criteria** | Archived with parent record |
| **Deletion Criteria** | Deleted with parent record |
| **Audit Frequency** | Assessed at every memory quality audit — context completeness is a primary quality metric |
| **Quality Gate** | All mandatory fields populated AND at least 5 of the optional fields populated |
| **Failure Modes** | Context poverty (insufficient fields — creates retrieval fog), context drift (context fields capture retrospective state, not event-time state), context contamination (wrong context attached to record) |
| **Related Primitives** | MPRIM-001 (Context belongs to Record), MPRIM-008 (Snapshot captures full context), MPRIM-016 (Working Memory State includes current context) |
| **Layer Owner** | Layer 2: MarketIntelligence |
| **Cross-Layer Use** | Layer 3 (MetaLearning — regime context), Layer 4 (OpportunityEngine — market context), Layer 10 (DebateAndDecision — decision context) |
| **Constitutional Constraints** | Principles M-001 (Complete Context), M-012 (Context Immutability), M-013 (Context Fidelity) |

### MPRIM-007: Memory Link

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-007 |
| **Primitive Name** | Memory Link |
| **Primitive Class** | Reference |
| **Definition** | A typed, directional connection between two memory records, episodes, or clusters that encodes the nature and strength of their relationship — the structural element that transforms isolated records into a living memory network |
| **Purpose** | Memory without links is a database. Links are what make memory associative — what enable one recalled memory to activate a wave of related memories, what enable the system to reason across time and context, and what enable pattern recognition at scale |
| **Memory Tier** | All tiers — Links exist between records at any tier combination |
| **Creation Event** | Created at memory creation (temporal and entity links), at learning consolidation (causal and lesson links), or at retrieval (recognized analogical links) |
| **Creation Authority** | Layer 17: ControlTower — structural links; Layer 13: LearningSystem — learning links; Layer 10: DebateAndDecision — analogical links created during reasoning |
| **Mandatory Fields** | link_id, source_record_id, target_record_id, link_type, link_strength, creation_time, creating_layer |
| **Optional Fields** | link_direction, bidirectional_flag, discovery_method, validation_count, last_activated |
| **Strength Range** | 0.0–1.0 — creation default: 0.4 for inferred links; 0.7 for evidence-based links; 1.0 for constitutional links |
| **Confidence Range** | 0.0–1.0 — reflects confidence that the relationship is genuine |
| **Decay Model** | Links decay at 0.02 per month without activation; structural links are decay-resistant |
| **Reinforcement Model** | Each activation of a link during retrieval increases link strength by 0.05; validated causal links gain 0.1 |
| **Consolidation Criteria** | Strength ≥ 0.5 AND activation_count ≥ 3 AND confidence ≥ 0.6 |
| **Retrieval Cues** | source_record_id, target_record_id, link_type — Links are discovered through endpoint traversal |
| **Association Types** | Links ARE associations — they do not have their own association type |
| **Update Policy** | link_strength and confidence may be updated; source, target, and type are immutable |
| **Version Policy** | Strength history tracked; point-in-time snapshots at consolidation |
| **Archival Criteria** | Strength < 0.1 AND no activation in 90 days AND link_type ≠ STRUCTURAL |
| **Deletion Criteria** | Either endpoint deleted, OR archived and archive age > 365 days |
| **Audit Frequency** | Monthly link quality audit; quarterly network topology review |
| **Quality Gate** | Both endpoints exist AND link_type is valid AND strength > 0.0 |
| **Failure Modes** | False link (spurious association), broken link (endpoint deleted), link flood (too many weak links degrade network quality), missing link (critical relationship not captured) |
| **Related Primitives** | MPRIM-001 (Records are link endpoints), MPRIM-004 (Clusters are link endpoints), MPRIM-005 (Index includes link traversal) |
| **Layer Owner** | Layer 17: ControlTower |
| **Cross-Layer Use** | All layers that perform associative retrieval — primarily Layers 3, 5, 10, 13 |
| **Constitutional Constraints** | Principles M-014 (Link Validity), M-015 (Association Governance) |

### MPRIM-008: Memory Snapshot

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-008 |
| **Primitive Name** | Memory Snapshot |
| **Primitive Class** | Storage |
| **Definition** | A complete, point-in-time capture of a defined domain of the memory system — preserving the entire state of that domain at a specific moment for future comparison, rollback, or audit |
| **Purpose** | Snapshots enable comparison — the most fundamental analytical operation. Without snapshots, the system cannot know how memory has changed, cannot detect drift, and cannot roll back to a known good state. Snapshots are to memory what the Mark-to-Market is to portfolio accounting: the hard anchor to which all drift is measured |
| **Memory Tier** | Long-term — Snapshots are created to persist; they are the institutional record |
| **Creation Event** | Triggered by: daily EOD cycle, regime transition, major event (crisis, policy decision), explicit audit request, or pre-upgrade checkpoint |
| **Creation Authority** | Layer 14: PerformanceAnalytics — performance snapshots; Layer 17: ControlTower — system snapshots |
| **Mandatory Fields** | snapshot_id, domain, snapshot_time, trigger_event, record_count, total_strength, coverage_metrics |
| **Optional Fields** | regime_state, strategy_states[], portfolio_state, risk_state, learning_state, comparative_delta_from_prior |
| **Strength Range** | Not applicable — Snapshot is a container; it has a completeness_score (0.0–1.0) instead |
| **Confidence Range** | 0.0–1.0 — reflects completeness of the snapshot; 1.0 = all records captured |
| **Decay Model** | Does not decay — Snapshots are preserved as historical truth |
| **Reinforcement Model** | Not applicable |
| **Consolidation Criteria** | Achieved at creation — Snapshots are immediately long-term |
| **Retrieval Cues** | domain, snapshot_time, trigger_event, regime_state |
| **Association Types** | Sequential (prior and next snapshot in the same domain), event-triggered (linked to the triggering event record) |
| **Update Policy** | Immutable after creation — Snapshots are frozen records of historical truth |
| **Version Policy** | Not versioned — each Snapshot is unique |
| **Archival Criteria** | Age > 2 years AND domain activity level is low AND superseded by later snapshots |
| **Deletion Criteria** | Never deleted — Snapshots are permanent institutional memory |
| **Audit Frequency** | Verified at each subsequent snapshot creation — delta analysis performed |
| **Quality Gate** | completeness_score ≥ 0.90 AND all mandatory fields populated |
| **Failure Modes** | Incomplete snapshot (domain not fully captured), snapshot timing error (created after the event rather than before), snapshot corruption (data integrity lost) |
| **Related Primitives** | MPRIM-001 (Snapshot captures Records), MPRIM-004 (Snapshot captures Clusters), MPRIM-024 (Provenance tracks Snapshot lineage) |
| **Layer Owner** | Layer 14: PerformanceAnalytics |
| **Cross-Layer Use** | Layer 15 (ResearchLab — for walk-forward baseline), Layer 16 (ValidationEngine), Layer 17 (ControlTower — audit) |
| **Constitutional Constraints** | Principles M-002 (Immutable History), M-016 (Snapshot Completeness) |

### MPRIM-009: Memory Retrieval Request

| Attribute | Specification |
|---|---|
| **Primitive Identifier** | MPRIM-009 |
| **Primitive Name** | Memory Retrieval Request |
| **Primitive Class** | Process |
| **Definition** | The formal specification of what memory is needed — including query parameters, context filters, strength thresholds, and expected result type — issued by a reasoning agent to the memory system |

## PART IV — THE 32 MEMORY TYPES

### The Architecture of Memory Types

Memory types classify memory by its primary function and operational role. Where Part II defined what memory is (670 vocabulary concepts) and Part III defined what memory does at its most fundamental level (25 primitives), Part IV defines the 32 distinct categories that memory falls into — each with its own creation trigger, storage requirements, decay model, retrieval mechanism, and governance rules.

The 32 memory types are not arbitrary — they correspond to the actual distinct functions that memory serves in the investment intelligence cycle. A type is defined as distinct when it has different creation triggers, different retrieval mechanisms, or different decay properties from all other types. No two types are redundant. Every memory created in the system is assigned exactly one primary type.

### MT-01: Working Memory — Detailed Specification

**Primary Function:** The dynamic, in-cycle memory that holds everything the system is actively reasoning with at this moment. Working memory is the system's cognitive workspace.

**Tier and Duration:** Working tier — exists only for the duration of one decision cycle; cleared at cycle completion or system restart.

**Creation Trigger:** Automatically created at the start of each decision cycle by Layer 10: DebateAndDecision; populated through directed retrieval from lower tiers.

**Storage Format:** In-memory object store — not persisted to disk during the cycle; cycle summary persisted to short-term at cycle completion.

**Retrieval Mechanism:** Direct access — working memory records do not require a retrieval request; they are already loaded. If a required memory is not in working memory, a Retrieval Request (MPRIM-009) is issued to the long-term or institutional tiers.

**Decay Model:** Immediate — working memory is cleared at cycle end. Records that must persist are explicitly promoted to short-term or long-term tier by the learning pipeline.

**Reinforcement Model:** Not applicable — working memory records are not reinforced; the records they were loaded from (in long-term) are reinforced through the Recall Event mechanism.

**Capacity:** Not unlimited — working memory has a capacity target of the most relevant 50 memory records for any cycle. Exceeding capacity triggers eviction of lowest-priority records and a cache miss scenario for the evicted content.

**Failure Modes:**
- **Context starvation:** Working memory loaded without required market context — decisions made on incomplete information
- **Stale loading:** Working memory populated with records from a prior session that were not cleared — anachronistic reasoning
- **Capacity overflow:** Too many records compete for working memory — eviction removes a record that was critical
- **Missing consolidation trigger:** Working memory contents not promoted at cycle end — experiential learning lost

**Decision Pipeline Integration:** All 5 debate agents draw from the shared working memory; DecisionEngine produces its output based on working memory state; ControlTower logs the working memory state at cycle completion.

**Constitutional Constraints:** Principles M-031 (Working Memory Completeness), M-032 (Context Priority Loading), M-047 (Cycle Isolation).

### MT-02: Episodic Memory — Detailed Specification

**Primary Function:** The narrative record of specific past market events, investment episodes, and trading experiences — preserving what happened, when it happened, in what sequence, and with what outcome.

**Tier and Duration:** Long-term — episodic memories persist across sessions and market cycles. Significant episodes (crisis events, major learning moments, outlier outcomes) may be promoted to institutional tier.

**Creation Trigger:** Trade closure (trade episode), session end (session episode), regime transition (regime episode), pattern confirmation or failure (pattern episode), crisis event detection (crisis episode).

**Storage Format:** Structured narrative — MPRIM-002 (Episode) + MPRIM-017 (Episodic Entry); contains temporal sequence, decision points, context snapshots, and lessons extracted.

**Retrieval Mechanism:** Temporal query (by date range), contextual query (by regime, instrument, or event type), analogical query (find most similar past episode to current situation).

**Decay Model:** Slow exponential — 0.01 strength per month without retrieval. High-significance episodes (absolute P&L > 2 sigma, or governance-designated) decay at 0.005 per month. Crisis episodes are decay-exempt.

**Reinforcement Model:** Retrieved and successfully used as analogue: +0.10. Lesson validated by outcome: +0.05. Repeated retrieval without use: no reinforcement.

**Key Use Cases:**
1. "The last time NIFTY fell 4% in one session — what happened next?" — analogical reasoning from episodic memory
2. "How did we behave during the Covid crash of March 2020?" — institutional learning from crisis episode
3. "What were our best performing weeks and what made them different?" — pattern extraction from episode review

**Failure Modes:**
- **Narrative collapse:** Episode summarized too briefly — useful analogues can't be matched because the episode lost its distinguishing features
- **Episode boundary confusion:** Records from two separate episodes merged — creates a chimeric memory with no real analogue
- **Lesson extraction failure:** Episode stored without lessons — episodic memory exists but cannot teach

**Constitutional Constraints:** Principles M-003 (Narrative Integrity), M-033 (Episodic Completeness), M-048 (Lesson Requirement).

### MT-03: Semantic Memory — Detailed Specification

**Primary Function:** The system's general knowledge about investment markets — the distilled principles, empirical regularities, and structural facts that apply across multiple episodes.

**Tier and Duration:** Institutional tier — semantic knowledge is the most permanent knowledge the system holds. Individual semantic entries are created only after validation across multiple episodes.

**Creation Trigger:** Created through formal learning consolidation: when a pattern is observed in ≥5 episodes with statistical confidence ≥0.6 and ResearchLab validation. Semantic entries are never created from a single episode.

**Storage Format:** MPRIM-018 (Semantic Entry) — concept, definition, validity conditions, supporting episodes, confidence score, exceptions.

**Retrieval Mechanism:** Keyword and concept-based query. Semantic memories are retrieved when reasoning requires general market knowledge rather than specific historical precedents.

**Decay Model:** Very slow — 0.002 per month. Contradicting evidence applies a sudden -0.10 penalty. A semantic entry with confidence below 0.3 is flagged for retirement.

**Reinforcement Model:** Confirming episode: +0.05. Peer review validation: +0.10. Published reference alignment: +0.03.

**Key Use Cases:**
1. "What is the typical behavior of Indian markets the day after a US market decline of 2%?" — semantic market knowledge
2. "What is the historical win rate of momentum strategies in trending regimes?" — semantic strategy knowledge
3. "What is the typical recovery time after NIFTY drawdowns of 10-15%?" — semantic regime knowledge

**Failure Modes:**
- **Premature generalization:** Semantic entry created from 2 episodes that happened to have the same outcome — spurious "principle"
- **Context stripping:** Semantic entry created without validity conditions — applied in contexts where it doesn't hold
- **Survivorship bias:** Semantic entries created from accessible episodes while failing episodes were not stored

**Constitutional Constraints:** Principles M-034 (Semantic Validity), M-035 (Generalization Standards), M-049 (Minimum Episodes for Generalization).

### MT-04: Procedural Memory — Detailed Specification

**Primary Function:** The system's operational knowledge — validated procedures for specific recurring situations. Procedural memory answers "how do we do this?" rather than "what do we know?"

**Tier and Duration:** Institutional tier — validated procedures are permanent. Deprecated procedures are archived with their deprecation record and replacement.

**Creation Trigger:** A procedure is created when a recurring situation has been handled successfully ≥10 times using the same sequence. Validation triggers promotion to procedural memory.

**Storage Format:** MPRIM-019 (Procedural Entry) — trigger conditions, step-by-step procedure, exceptions, validation history, performance metrics.

**Retrieval Mechanism:** Trigger-condition matching — when a situation is detected that matches a procedure's trigger conditions, the procedure is automatically loaded into working memory. Pattern-based retrieval in ambiguous situations.

**Decay Model:** Very slow — 0.001 per month. Procedures are reviewed quarterly. If trigger conditions become unreachable (market structure change), procedure is flagged for retirement.

**Reinforcement Model:** Successful application: +0.05. Application during novel conditions that extend the procedure's scope: +0.10.

**Key Use Cases:**
1. Gap-down open procedure: "If NIFTY opens down ≥2%, follow this sequence: check global context → check options chain → assess liquidity → execute hedges before any new positions"
2. Risk breach procedure: "If drawdown exceeds 1%, follow this sequence: freeze new entries → assess existing positions → execute graduated reduction"
3. Expiry day procedure: "On F&O expiry Thursdays, apply these position limits and monitoring frequencies"

**Failure Modes:**
- **Trigger miss:** Current situation matches procedure's intent but not its trigger_conditions field — procedure not retrieved
- **Procedure staleness:** Step references obsolete component that no longer exists
- **Procedural drift:** Agents informally adapt the procedure without updating the stored version — actual behavior diverges from recorded procedure

**Constitutional Constraints:** Principles M-036 (Procedure Validity), M-037 (Operational Reliability), M-050 (Procedure Testing).

### MT-05: Institutional Memory — Detailed Specification

**Primary Function:** The accumulated wisdom of the system across its entire operational lifetime — the highest-tier knowledge that is always available, never decays, and governs all reasoning.

**Tier and Duration:** Institutional tier, permanent. Institutional memory is the only memory type that is never subject to decay, archival, or deletion. It may only be superseded through formal governance process.

**Creation Trigger:** Created through formal multi-layer review — not automated. Typically created at: (1) resolution of a major crisis with extracted lessons, (2) completion of a major operational milestone, (3) annual governance review of accumulated wisdom.

**Storage Format:** MPRIM-020 (Institutional Entry) — content, creating agents, approving agents, source experiences, institutional category, precedence level.

**Retrieval Mechanism:** Category-based retrieval — institutional memories in relevant categories are loaded into every major decision context automatically. No threshold filtering — institutional memories are always retrieved when their category is relevant.

**Decay Model:** None — Institutional memory does not decay.

**Reinforcement Model:** Not applicable — permanently at maximum strength.

**Key Use Cases:**
1. "We have learned that risk management must never be suspended in response to confidence — conviction creates risk, not reduces it"
2. "Strategies that perform well in simulated backtests but have never been tested in live markets begin with maximum position restrictions"
3. "The system must never make decisions that are irreversible without explicit governance review"

**Failure Modes:**
- **Inflation:** Too many lessons promoted to institutional level — the category loses its meaning and its most important entries are buried
- **Stagnation:** Institutional memory not updated when market structure changes fundamentally — outdated wisdom is applied to inapplicable conditions
- **Opacity:** Institutional memory exists but is not retrieved in the decision contexts where it is relevant

**Constitutional Constraints:** Principles M-038 (Institutional Integrity), M-039 (Governance of Permanence), M-051 (Institutional Memory Scope).

### MT-08: Crisis Memory — Detailed Specification

**Primary Function:** The preservation of extreme market events — crashes, liquidity crises, circuit breakers, black swan events — and the system's behavior, decisions, and outcomes during them.

**Tier and Duration:** Institutional tier — crisis memories are permanently preserved. Unlike other institutional memories, crisis memories preserve full detail, not compressed summaries, regardless of age.

**Creation Trigger:** Triggered when: (1) daily P&L loss exceeds 3 sigma of historical distribution, (2) VIX exceeds 45, (3) circuit breaker triggered, (4) liquidity score drops below critical threshold, or (5) explicit crisis designation by RiskGuardian.

**Storage Format:** Full-detail MPRIM-002 (Episode) with MPRIM-008 (Snapshot) captured at crisis onset, peak, and resolution. No compression ever applied.

**Retrieval Mechanism:** Pattern-triggered retrieval — when current conditions match crisis signatures from historical crisis memories, those memories are automatically surfaced in working memory. Crisis memories override normal retrieval priority ordering.

**Decay Model:** None — Crisis memories are decay-exempt.

**Reinforcement Model:** Each time a crisis memory prevents an incorrect decision: +0.10.

**Key Use Cases:**
1. "Current VIX spike pattern matches March 2020 crisis memory — load crisis playbook and reduce all new entries"
2. "Liquidity conditions resemble 2008 global crisis memory — apply maximum position restriction protocol"
3. "Post-crisis recovery signals match historical crisis memory recovery patterns — gradually resume normal operation"

**Failure Modes:**
- **Crisis not recognized:** Current conditions match crisis signatures but memory not retrieved because pattern matching threshold is too high
- **Over-triggering:** Non-crisis volatility triggers crisis memory retrieval — all decisions become excessively conservative
- **Missing crisis memory:** A crisis occurred that was not captured with full detail — the lesson is lost

**Constitutional Constraints:** Principles M-008 (Crisis Preservation), M-052 (Crisis Detail Retention), M-053 (Crisis Pattern Recognition).

### MT-09: Pattern Memory — Detailed Specification

**Primary Function:** Memory of recurring market patterns — their structure, conditions, historical frequency, reliability, and performance statistics.

**Tier and Duration:** Long-term — Pattern memories persist indefinitely; frequently validated patterns may be promoted to institutional tier.

**Creation Trigger:** Created when a pattern has been observed and confirmed across ≥3 market cycles. Initial detection creates an observation record; promotion to pattern memory requires validation.

**Storage Format:** Structured pattern specification: pattern name, conditions, historical occurrences, win rate, average return, regime sensitivity, sample size, last confirmed date.

**Retrieval Mechanism:** Condition-based matching — when current market conditions match a stored pattern's conditions, that pattern memory is surfaced automatically. Similarity search when exact match fails.

**Decay Model:** Slow — 0.01 per month without confirmation. If a pattern fails to appear for 12 consecutive months when conditions are met, it enters review. If 3 consecutive failures occur after pattern conditions are met, strength is reduced by 0.2.

**Reinforcement Model:** Each confirmed occurrence: +0.05. Profitable trade aligned with pattern: +0.08.

**Key Use Cases:**
1. "Opening range breakout pattern — when NIFTY breaks above the first 15-minute high after a flat open, direction is maintained 68% of the time"
2. "Pre-expiry consolidation pattern — NIFTY ranges in a narrow band for 2-3 days before monthly expiry, then breaks sharply"
3. "RBI surprise pattern — surprise rate cuts produce a 2% intraday spike followed by mean reversion within 3 sessions"

**Failure Modes:**
- **Pattern mining bias:** Pattern created from in-sample data — does not generalize to out-of-sample periods
- **Pattern obsolescence:** Market structure changes and pattern stops working, but memory persists and continues to influence decisions
- **Pattern crowding:** A pattern becomes widely known and traded, eliminating the edge it once represented

**Constitutional Constraints:** Principles M-009 (Pattern Validation), M-054 (Minimum Sample Size), M-055 (Regime Sensitivity Documentation).

---

### MT-10: Regime Memory — Detailed Specification

**Primary Function:** Memory of market regimes — their defining characteristics, typical duration, transition signals, and the performance of each strategy within each regime.

**Tier and Duration:** Long-term — Regime memories are among the most valuable and most stable knowledge the system holds.

**Creation Trigger:** Created when a regime transition is confirmed by MarketIntelligence. Each regime period generates a regime memory entry upon conclusion.

**Storage Format:** Regime descriptor: regime_type, start_date, end_date, VIX_range, trend_direction, breadth_characteristics, dominant_sectors, strategy_performances, transition_signals.

**Retrieval Mechanism:** Condition-based — when MarketIntelligence classifies the current regime, matching regime memories are retrieved. Historical performance of all strategies in this regime type is surfaced for MetaLearning.

**Decay Model:** Slow — 0.005 per month. Regime memories are never fully discarded because even rare regimes may recur.

**Reinforcement Model:** Successful strategy selection based on regime memory: +0.08. Correct regime transition prediction: +0.12.

**Key Use Cases:**
1. "Current regime classified as TRENDING_BULL — load regime memory for trending bull periods; momentum strategies outperform by 3.2% average per month"
2. "Regime transition signals detected — retrieve memories of transitions from TRENDING_BULL to HIGH_VOLATILITY; typical duration of transition: 3-7 days"
3. "SIDEWAYS_LOW_VOL regime — retrieve memory; mean-reversion strategies preferred; typical NIFTY daily range 0.4-0.8%"

**Failure Modes:**
- **Regime misclassification:** Memory for wrong regime type retrieved — strategy allocation inappropriate for actual conditions
- **Regime stacking:** New regime memory overwrites old rather than adding — historical regime performance data lost
- **Sparse regime memory:** Some regime types have too few historical examples — insufficient statistical confidence for strategy allocation

**Constitutional Constraints:** Principles M-010 (Regime Coverage), M-056 (Regime Transition Signals), M-057 (Regime Performance Attribution).

---

### MT-14: Risk Memory — Detailed Specification

**Primary Function:** Memory of risk events, risk thresholds, risk governance decisions, and the system's behavior and performance during high-risk conditions.

**Tier and Duration:** Institutional — Risk memory is the most safety-critical memory type. All significant risk events are permanently preserved in full detail.

**Creation Trigger:** Created when: (1) a risk threshold is triggered, (2) a risk governance intervention occurs, (3) daily P&L loss exceeds 1%, (4) a drawdown exceeds 5%, or (5) a position is closed due to risk governance.

**Storage Format:** Structured risk event: event_type, trigger_time, trigger_condition, conditions_at_trigger, action_taken, outcome, lesson_extracted, recovery_timeline.

**Retrieval Mechanism:** Pattern-triggered — current risk conditions matched against historical risk event memory. Risk memories are loaded into working memory whenever risk metrics approach historical trigger levels.

**Decay Model:** Very slow — 0.001 per month for risk events. No decay for events involving losses > 2% of capital.

**Reinforcement Model:** Risk memory that correctly predicts a risk event: +0.15.

**Key Use Cases:**
1. "Current drawdown at 1.8% — retrieve memory of similar drawdown trajectories; 73% of drawdowns that reached 1.8% continued to 2.5% — apply preemptive reduction"
2. "VIX spike pattern — retrieve risk memory for similar VIX spikes; typical duration before normalization: 3-7 days"
3. "Correlation breakdown detected — retrieve risk memory for correlation breakdown events; options hedges outperform during these periods"

**Failure Modes:**
- **Risk memory gap:** A type of risk event occurs for which no historical memory exists — response is improvised
- **Risk memory obsolescence:** Market structure changes the relationship between risk signals and risk events — old risk memories lead to incorrect responses
- **Insufficient granularity:** Risk memory preserved at too high a level of abstraction — specific trigger conditions lost

**Constitutional Constraints:** Principles M-058 (Risk Memory Completeness), M-059 (Risk Event Preservation), M-060 (Risk Governance Accountability).

---

### MT-25: Learning Memory — Detailed Specification

**Primary Function:** Memory of learning events, lessons extracted, knowledge updates, and the evolution of the system's understanding over time — the meta-record of how intelligence learns.

**Tier and Duration:** Long-term — Learning memories are preserved as the institutional record of how knowledge was acquired and updated.

**Creation Trigger:** Created at each formal learning event: strategy evaluation, pattern confirmation, lesson extraction, belief update, calibration adjustment.

**Storage Format:** Learning event record: lesson_type, trigger_event, prior_belief, updated_belief, evidence, confidence_change, application_domain.

**Retrieval Mechanism:** Domain-based retrieval — when a decision requires knowing what has been learned in a specific area, the learning memories for that area are retrieved. Lesson type filtering narrows the retrieval.

**Decay Model:** Very slow — 0.002 per month. Learning memories of lessons that continue to be applied do not decay.

**Reinforcement Model:** Lesson successfully applied and confirmed: +0.10.

**Key Use Cases:**
1. "We have learned that our initial position sizing for new strategies should be reduced by 50% — retrieve the learning events that established this"
2. "Conviction calibration learning — retrieve the history of conviction score adjustments and their outcomes"
3. "What have we learned about entry timing on expiry days? — retrieve all learning events tagged with 'expiry' and 'entry'"

**Failure Modes:**
- **Lesson not extracted:** Experience occurs but formal learning event not created — knowledge not encoded
- **Lesson conflict:** Two learning events produce contradictory lessons — neither is applied correctly
- **Lesson regression:** A lesson is learned, then forgotten as the underlying memory decays — error is repeated

**Constitutional Constraints:** Principles M-061 (Learning Completeness), M-062 (Lesson Extraction), M-063 (Lesson Application Tracking).

## PART V — THE 26-STAGE MEMORY PIPELINE

### Pipeline Philosophy

The memory pipeline is not a processing sequence for creating isolated records. It is the full lifecycle of how intelligence transforms experience into knowledge, knowledge into memory, and memory into future intelligence. The pipeline runs in two directions simultaneously: **forward** (experience → memory creation → storage), and **backward** (query → retrieval → reasoning support). These two flows interact throughout — active retrieval from long-term memory shapes how new experiences are encoded, while new encodings update what future retrievals will find.

The 26 stages cover the complete arc from the arrival of raw market information to the archival of wisdom, and from a decision agent's query to the delivery of relevant memory to its reasoning process.

### Stage 01 — Information Arrival

**Function:** The entry point of all market intelligence — raw information arriving from any source: data feeds, execution events, external news, or internal computation.

**Inputs:** Raw market data (price, volume, options chain), execution events, news signals, global intelligence snapshots, macro data, peer system outputs.

**Process:** Each arriving datum is time-stamped at arrival and classified by source tier. A Memory Trace (MPRIM-003) is created immediately to ensure no arrival is lost to processing latency. The trace captures: source, arrival time, data type, and initial value. This trace is the memory system's receipt for the event — confirmation that the event is being processed.

**Outputs:** Memory Trace (MPRIM-003) with arrival timestamp and source classification.

**Timing:** Continuous — runs at real-time market data frequency during market hours; batch at EOD for global data.

**Owner Layer:** Layer 2: MarketIntelligence (market data), Layer 1: GlobalIntelligence (global data), Layer 11: ExecutionEngine (execution events).

**Failure Modes:**
- Data feed disconnection: arrival stream interrupted — Trace cannot be created — gap in memory record
- Timestamp error: arrival time inaccurate — temporal reasoning corrupted
- Source misclassification: high-quality source classified as low-quality — memory incorrectly weighted

---

### Stage 02 — Observation Registration

**Function:** Transforms a raw Memory Trace into a complete Observation Record — a structured representation of the event with source, value, and quality assessment.

**Inputs:** Memory Trace from Stage 01; data quality checks; source reliability lookup.

**Process:** The Observation Record extends the Trace with: structured data extraction (closing price = 24,305; volume = 12.4M units), source reliability score (yfinance tier 2 data = 0.85 reliability), data quality assessment (within expected range, no anomaly flags), and initial contextual tags (NIFTY cash market, close price, 2026-07-02).

**Outputs:** Observation Record (MPRIM-001, type=OBSERVATION) with quality-assessed, structured data.

**Timing:** Immediately following Stage 01 — pipeline completes Stages 01-02 within the data arrival cycle.

**Owner Layer:** Layer 2: MarketIntelligence.

**Failure Modes:**
- Quality assessment failure: anomalous value not flagged — erroneous data enters memory as fact
- Structured extraction error: incorrect field mapping — data stored in wrong memory field
- Duplicate registration: same event registered twice — memory duplication

---

### Stage 03 — Decision Commitment

**Function:** The act of making a trading decision creates an immediate memory record — the commitment itself is a memory event, regardless of whether the decision leads to execution.

**Inputs:** Decision Engine output from Layer 10, including the decision type, conviction score, evidence summary, and decision reasoning chain.

**Process:** At the moment a decision is committed (approved by DecisionEngine), a Decision Memory Record (MPRIM-001, type=DECISION) is created capturing: the decision (BUY / SELL / HOLD), the instrument, the conviction score, the evidence summary, the timestamp, the approving governance gate, the five-agent debate summary, and the working memory state at time of decision. This record is the pre-outcome anchor — what was believed before the outcome was known.

**Outputs:** Decision Memory Record; update to Working Memory State (MPRIM-016) to reflect committed decision.

**Timing:** Synchronous with DecisionEngine commitment — no latency permitted between decision and memory creation.

**Owner Layer:** Layer 10: DebateAndDecision; Layer 17: ControlTower logs.

**Failure Modes:**
- Decision recorded post-hoc: memory created after outcome is known — contaminated by hindsight
- Incomplete debate capture: five-agent consensus not fully recorded — reasoning audit fails
- Conviction score omitted: calibration training data incomplete

---

### Stage 04 — Outcome Observation

**Function:** The market delivers an outcome — price movement, execution quality, P&L realization — which is captured as the second half of the decision record.

**Inputs:** Execution confirmation from ExecutionEngine; real-time P&L from TradeMonitoring; exit price and exit conditions.

**Process:** The Outcome Record (MPRIM-001, type=OUTCOME) is linked to its paired Decision Record from Stage 03. The outcome captures: entry price, exit price, realized P&L, trade duration, exit trigger (target hit, stop triggered, time exit, governance exit), slippage, market conditions at exit, and the deviation of outcome from prediction. This pair — Decision → Outcome — is the fundamental learning dyad.

**Outputs:** Outcome Record linked to Decision Record; updated Working Memory State.

**Timing:** At trade closure or at EOD for open positions (preliminary outcome).

**Owner Layer:** Layer 12: TradeMonitoring; Layer 11: ExecutionEngine.

**Failure Modes:**
- Orphaned decision: outcome not linked to its decision record — learning dyad broken
- Incomplete outcome: exit conditions not captured — attribution impossible
- Mark-to-market error: unrealized P&L incorrectly calculated — learning signal distorted

---

### Stage 05 — Learning Event Creation

**Function:** The Decision-Outcome pair is analyzed by the Learning System to extract a formal Learning Event — the structured lesson from the experience.

**Inputs:** Decision Record + Outcome Record pair; historical context; attribution analysis; pattern matching results.

**Process:** Layer 13 (LearningSystem) processes the decision-outcome pair with a formal attribution analysis: which signals predicted correctly? Which predicted incorrectly? What was the contribution of each agent's recommendation? What was the regime? What was the pattern? A Learning Event record is created with these answers. The Learning Event also checks for pattern confirmation or pattern failure, conviction calibration data points, and strategy performance update signals.

**Outputs:** Learning Event Record (MPRIM-001, type=LEARNING_EVENT) with attribution and lesson draft; signal update requests to MetaLearning.

**Timing:** Within one cycle after outcome confirmation; full analysis at EOD.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- Attribution failure: cause of outcome not correctly identified — lesson learned is wrong
- Missing learning event: decision-outcome pair analyzed but no Learning Event created — experience wasted
- Premature lesson: learning event created before full outcome is observed — incomplete learning

---

### Stage 06 — Memory Creation Trigger

**Function:** Determines whether the Learning Event is significant enough to create a new memory record or update an existing one.

**Inputs:** Learning Event from Stage 05; significance assessment; thresholds for memory creation.

**Process:** The Memory Creation Trigger evaluates significance along four dimensions: (1) magnitude — is the P&L outcome beyond 0.5 sigma? (2) novelty — does this event contain any patterns not already in memory? (3) error — does this event represent a new type of error? (4) governance — was any governance threshold triggered? Any "yes" creates a memory. Routine, expected events within prediction bounds update existing records rather than creating new ones.

**Outputs:** Memory creation authorization; target record identification (create new OR update existing).

**Timing:** Immediate following Stage 05.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- Under-triggering: significant events not triggering memory creation — learning gap
- Over-triggering: every event creates a new memory — memory explosion, network dilution
- Incorrect target: event updates wrong existing record — memory contamination

---

### Stage 07 — Memory Classification

**Function:** Assigns the authorized new memory to its primary type (one of the 32 MT types), its tier (working/short-term/long-term/institutional), and its governance category.

**Inputs:** Learning Event record; event type; significance score; governance flags.

**Process:** Classification applies a decision tree: Is this about a specific past event? → Episodic (MT-02). Is this a generalized principle? → Semantic (MT-03). Is this about how to perform a task? → Procedural (MT-04). Is this from a crisis? → Crisis (MT-08). Is this about a strategy? → Strategy (MT-11). Classification also assigns the initial tier based on significance: routine observations begin at short-term; significant events at long-term; crisis events and governance decisions at institutional.

**Outputs:** Memory type classification; tier assignment; governance category tag.

**Timing:** Immediate following Stage 06.

**Owner Layer:** Layer 13: LearningSystem; Layer 17: ControlTower.

**Failure Modes:**
- Misclassification: episodic memory classified as semantic — treated as general principle when it is a specific event
- Tier assignment error: institutional-significance event assigned to short-term — subject to decay when it should be permanent
- Type conflict: event could legitimately belong to multiple types — ambiguous classification

---

### Stage 08 — Memory Content Extraction

**Function:** Extracts the precise content that will be stored in the memory record — defining what the memory actually says.

**Inputs:** Learning Event record; raw event data; decision record; outcome record.

**Process:** Content extraction populates all mandatory fields for the classified memory type: for an episodic memory, this means the narrative summary, key decision points, and lesson draft. For semantic memory, this means the concept statement and validity conditions. For pattern memory, this means the pattern conditions and performance statistics. Content extraction also applies clarity standards: ambiguous content triggers a clarification request rather than storage of unclear information.

**Outputs:** Populated content fields for the memory record; clarity assessment.

**Timing:** Immediate following Stage 07.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- Vague content: summary too general to be analytically useful
- Missing lesson: episodic memory created without lesson extraction — experience stored without learning
- Excess detail: content too granular — retrieval becomes noisy and slow

---

### Stage 09 — Memory Context Assignment

**Function:** Attaches the full contextual wrapper (MPRIM-006) to the memory record — the conditions under which the memory was created.

**Inputs:** Memory record from Stage 08; current market context from MarketIntelligence; current regime from MetaLearning; global context from GlobalIntelligence.

**Process:** Context is captured at the time of the original event (not at the time of memory creation — these may differ). Context fields populated: regime, market phase, volatility level, liquidity state, sector conditions, global conditions, calendar context (expiry, earnings season, budget), FII flow direction, and sentiment level. Context quality is assessed — a memory with fewer than 5 context fields populated is flagged for supplemental context.

**Outputs:** MPRIM-006 (Memory Context) attached to the memory record; context completeness score.

**Timing:** Immediate — context must be captured while current, not retrospectively.

**Owner Layer:** Layer 2: MarketIntelligence; Layer 1: GlobalIntelligence.

**Failure Modes:**
- Context lag: context captured from current state rather than event-time state — anachronistic memory
- Context poverty: fewer than 5 context fields populated — retrieval fog (similar memories can't be distinguished by context)
- Context contamination: wrong regime or market phase attached

---

### Stage 10 — Memory Strength Initialization

**Function:** Assigns the initial strength value to the new memory record — calibrated by memory type, event significance, and source reliability.

**Inputs:** Memory type (from Stage 07); significance score; source reliability; outcome magnitude.

**Process:** Strength initialization follows type-specific rules: Governance records begin at 1.0. Observed, confirmed outcomes begin at 0.8. Learning events begin at 0.7. Inferred patterns begin at 0.6. Preliminary observations begin at 0.5. Uncertain inferences begin at 0.3. The initialization also considers significance multiplier: a 3-sigma outcome multiplies the base strength by 1.2 (capped at 1.0).

**Outputs:** strength field in memory record set to calibrated initial value.

**Timing:** Immediate following Stage 09.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- Strength inflation: routine events initialized too high — clutter high-priority retrieval
- Strength suppression: significant events initialized too low — missed in retrieval
- Missing significance multiplier: outlier event initialized at standard strength — not flagged for priority

---

### Stage 11 — Memory Confidence Assignment

**Function:** Assigns the initial confidence value — reflecting certainty about the accuracy of what the memory contains.

**Inputs:** Source reliability; evidence quality; attribution confidence from Learning Event; contradiction check against existing memories.

**Process:** Confidence is not certainty — it is an honest estimate of how accurate the memory's content is. Directly observed and confirmed: 0.9. Inferred from multiple strong signals: 0.8. Inferred from single signal: 0.6. Derived from model output: 0.5. Speculative or preliminary: 0.3. Confidence is additionally reduced if: the source has a history of errors (−0.1 per error on record), the content contradicts existing high-confidence memories without strong evidence (−0.15), or attribution is not clear (−0.1).

**Outputs:** confidence field in memory record set to calibrated initial value.

**Timing:** Immediate following Stage 10.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- Overconfidence initialization: memory begins at 0.9 when evidence warrants 0.6 — system trusts it too much
- Contradiction not checked: new memory contradicts existing without flagging — silent conflict created

---

### Stage 12 — Memory Linking

**Function:** Connects the new memory to related existing memories through typed associations — making it part of the living memory network rather than an isolated record.

**Inputs:** New memory record; index query for related memories; association type rules.

**Process:** The linking engine queries the index for memories that share: (1) the same entity (instrument, sector, strategy), (2) the same time period (temporal proximity within 5 trading days), (3) the same regime (same regime classification), (4) the same pattern (pattern records with matching conditions). For each match, a Memory Link (MPRIM-007) is created with the appropriate type (temporal, entity, causal, analogical, structural) and strength. The new memory is also linked to its parent episode.

**Outputs:** Memory Links (MPRIM-007) connecting the new memory to related records; parent episode link.

**Timing:** Within the creation cycle — must complete before the memory is indexed.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- No links created: new memory becomes an isolated record — associative retrieval will never find it
- Too many links: memory linked to all records that share any feature — network dilution, slow retrieval
- Wrong link type: temporal link created where causal was appropriate — reasoning from wrong association

---

### Stage 13 — Memory Indexing

**Function:** Registers the new memory in all applicable indices so that retrieval queries can find it efficiently.

**Inputs:** New memory record with all fields populated; links from Stage 12.

**Process:** The indexing engine adds the memory to: (1) the temporal index (keyed by event_time and creation_time), (2) the entity index (keyed by instrument, sector, strategy), (3) the regime index (keyed by regime classification from context), (4) the type index (keyed by memory type and tier), (5) the content index (keyword extraction from summary and lesson fields), and (6) the strength index (sorted by strength for priority retrieval). Each index entry includes the memory_id, key value, and retrieval score hint.

**Outputs:** Index entries in all applicable indices; integrity hash updated.

**Timing:** Immediate following Stage 12 — memory is not retrievable until indexed.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Missing index entry: memory created but not indexed — permanently unretrievable
- Wrong key: indexed under incorrect entity or time — retrieval finds it in wrong context
- Index corruption: integrity hash mismatch — index entry invalidated at next audit


---

### Stage 14 — Memory Prioritization

**Function:** Assigns a retrieval priority score — determining where this memory ranks in competitive retrieval when many memories qualify for the same query.

**Inputs:** Strength, confidence, memory type, tier, regime relevance, recency.

**Process:** Priority score = (strength × 0.35) + (confidence × 0.25) + (recency_factor × 0.20) + (regime_relevance × 0.15) + (type_weight × 0.05). Type weights: institutional = 1.0, long-term governance = 0.95, crisis = 0.9, episodic and semantic = 0.8, pattern and regime = 0.75, routine observation = 0.6. Priority score is stored in the priority index and updated at every reinforcement and decay event.

**Outputs:** Priority score in memory record; priority index entry.

**Timing:** Immediate following Stage 13.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Priority stagnation: priority not updated after reinforcement or decay — stale ordering
- Type weight miscalibration: routine observations outranking institutional entries — critical memory buried

---

### Stage 15 — Working Memory Registration

**Function:** For memories needed in the current decision cycle, loads the new memory into the active Working Memory State (MPRIM-016).

**Inputs:** New memory record; current Working Memory State; capacity availability.

**Process:** After indexing and prioritization, if the new memory's priority score is above the working memory loading threshold AND the current cycle has not yet committed its decision, the memory is loaded into the active Working Memory State. If working memory is at capacity, the lowest-priority currently-loaded record is evicted (logged as eviction event) and the new record is loaded. The load event is recorded in the Working Memory State's loaded_records list.

**Outputs:** Updated Working Memory State with new record loaded; eviction log if capacity reached.

**Timing:** Conditional — only runs for in-cycle memories during active decision pipeline.

**Owner Layer:** Layer 10: DebateAndDecision.

**Failure Modes:**
- Load delay: high-priority memory created but not loaded until next cycle — missed in current decision
- Eviction of critical record: capacity management evicts a record that was more important than the new arrival
- Working memory not updated: memory created but Working Memory State object not refreshed

---

### Stage 16 — Short-Term Memory Storage

**Function:** Persists the memory to the short-term tier — moving it from transient in-cycle state to persistent multi-session storage.

**Inputs:** New memory record; tier assignment from Stage 07.

**Process:** Short-term storage persists the memory record to disk (or equivalent durable medium) with a retention tag indicating the expected duration before consolidation review: 24 hours for routine observations, 7 days for session-level learning, 30 days for significant events awaiting consolidation. The short-term store maintains an ordered queue by consolidation review date. A short-term index is built for efficient retrieval during the review period.

**Outputs:** Persisted memory record in short-term store; consolidation review schedule entry.

**Timing:** At cycle end or at session end for in-cycle memories; immediately for memories classified as short-term from Stage 07.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Storage failure: memory not persisted — lost at session end
- Retention period error: memory scheduled for 24-hour review when it warrants 30 days
- Short-term index not updated: new record not findable in retrieval queries during review period

---

### Stage 17 — Memory Consolidation Assessment

**Function:** The scheduled review that determines whether a short-term memory has earned promotion to long-term storage, or should be discarded.

**Inputs:** Short-term memory queue; consolidation criteria for each memory type; evidence of validation or use.

**Process:** At each scheduled consolidation cycle (daily EOD), Layer 13 reviews the consolidation queue. For each candidate, the assessment evaluates: (1) strength ≥ consolidation threshold for this type, (2) at least one successful retrieval since creation, (3) confidence meets minimum, (4) no unresolved conflicts, (5) all mandatory fields populated. A pass on all criteria triggers promotion. A fail triggers a second review in 7 days. A second consecutive fail triggers discard. The assessment is recorded as a Memory Consolidation Record (MPRIM-011).

**Outputs:** Consolidation decision (promote / defer / discard); Consolidation Record (MPRIM-011).

**Timing:** Daily EOD; triggered on demand for urgent high-value memories.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- False discard: valuable memory fails consolidation due to assessment error — permanently lost
- False promotion: low-quality memory promoted — long-term store polluted
- Consolidation backlog: queue grows faster than it is processed — important memories expire before assessment

---

### Stage 18 — Long-Term Memory Transfer

**Function:** Physically moves a memory that has passed consolidation assessment from the short-term store to the long-term store.

**Inputs:** Consolidation approval from Stage 17; memory record.

**Process:** Transfer involves: (1) creating a Memory Version Record (MPRIM-021) capturing the state at transfer time, (2) writing the record to long-term store with updated tier tag, (3) updating all indices to reflect new storage location, (4) updating links to reflect tier change, (5) logging the transfer in the Consolidation Record, and (6) removing the record from the short-term store. Transfer is atomic — either fully completes or fully rolls back. Partial transfer is not permitted.

**Outputs:** Memory record in long-term store; updated indices; transfer logged in Consolidation Record.

**Timing:** Immediately following consolidation approval.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Transfer not atomic: memory deleted from short-term before long-term write completes — record lost
- Index not updated: record transferred but retrieval still queries short-term location — unfindable
- Link pointers not updated: existing links point to short-term location that no longer holds the record

---

### Stage 19 — Memory Cluster Assignment

**Function:** Assigns the newly long-term memory to one or more Memory Clusters (MPRIM-004) based on its type, domain, and context.

**Inputs:** Long-term memory record; cluster registry; clustering criteria.

**Process:** The cluster assignment engine queries the cluster registry for clusters whose organizing principles match the memory's entity, regime, strategy, or type. The memory is added to all matching clusters. If no matching cluster exists and the domain has accumulated ≥20 records, a new cluster is created. Cluster cohesion scores are recalculated after each assignment. A Memory Link (MPRIM-007) of type CLUSTER is created from the memory to each assigned cluster.

**Outputs:** Updated cluster membership; new cluster created if needed; cluster-type Memory Links created.

**Timing:** Within the transfer cycle.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- No cluster assignment: memory not assigned to any cluster — bulk retrieval misses it
- Wrong cluster assignment: memory assigned to cluster whose organizing principle is incompatible — cluster pollution
- Cluster not created when warranted: domain exceeds 20 uncluttered records but no clustering occurs — retrieval inefficiency

---

### Stage 20 — Memory Reinforcement (on recall)

**Function:** Strengthens a memory each time it is successfully retrieved and used in a reasoning or decision process.

**Inputs:** Recall Event (MPRIM-010) with positive use_outcome; retrieved memory record.

**Process:** Upon confirmation that a recalled memory contributed to a correct prediction, validated pattern, or successful decision, Layer 13 creates a Reinforcement Record (MPRIM-013) and applies the reinforcement: strength += reinforcement_magnitude (type-calibrated). Reinforcement also cascades to closely linked memories (MPRIM-007 links with strength > 0.6) at 50% of the primary reinforcement magnitude. The priority score is recalculated following reinforcement.

**Outputs:** Updated memory strength; updated priority score; Reinforcement Record (MPRIM-013); cascade reinforcement applied to linked records.

**Timing:** Within one cycle of the Recall Event with confirmed positive outcome.

**Owner Layer:** Layer 13: LearningSystem.

**Failure Modes:**
- Reinforcement delay: positive outcome confirmed but reinforcement not applied until next batch — missed reinforcement
- Misattribution: reinforcement applied to the wrong memory — incorrect memory strengthened
- Cascade over-spread: reinforcement cascades to distantly related memories — dilutes reinforcement signal

---

### Stage 21 — Memory Decay Application

**Function:** Reduces the strength of memories that have not been recently used — ensuring that stale, unused knowledge does not persist at the same priority as fresh, active knowledge.

**Inputs:** Memory records with last_accessed date; decay model parameters by type; current date.

**Process:** The decay engine runs nightly on all active memory records. For each record, it calculates: elapsed time since last access, the applicable decay model (exponential, linear, or stepped by type), and the new strength after decay. If new strength falls below the floor threshold: strength = max(new_strength, floor). If strength falls below the archival threshold, the record is added to the consolidation review queue for assessment for archival. A Decay Record (MPRIM-012) is created for each decay event that reduces strength by > 0.05.

**Outputs:** Updated strength values across all memory records; Decay Records (MPRIM-012) for significant decay events; archival candidates identified.

**Timing:** Nightly EOD cycle.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Decay skipped: nightly cycle fails — memories accumulate at incorrect strengths
- Decay model miscalibration: wrong decay rate applied — memories decay too fast (institutional knowledge lost) or too slow (stale content persists)
- Preservation not applied: high-value memory subject to standard decay when it should be decay-resistant

---

### Stage 22 — Memory Compression (on age)

**Function:** Reduces the detail of aged but still potentially relevant memories — preserving essential information while reducing storage volume and retrieval noise.

**Inputs:** Memory records meeting compression criteria: strength in range 0.2–0.5, age > 180 days, last accessed > 60 days ago.

**Process:** Compression creates a condensed version of the memory — retaining: memory type, event date, key outcome, primary lesson, and top 3 context tags. Detail lost in compression: full reasoning chain, intermediate steps, secondary lessons, raw data points. The original is moved to archive; the compressed version takes its place in long-term storage. A Compression Record (MPRIM-022) documents what was retained and what was lost.

**Outputs:** Compressed memory record in long-term store; original in archive; Compression Record (MPRIM-022).

**Timing:** Quarterly compression cycle; triggered for specific records when storage thresholds are approached.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Over-compression: key information (outcome magnitude, specific context) lost in compression
- Premature compression: memory compressed before it has had a chance to be retrieved and validated
- Compression of institutional-grade content: institutional entries should never be compressed — governance failure if this occurs

---

### Stage 23 — Memory Archive (on low priority)

**Function:** Formally transitions memories below the active retrieval threshold to the archive tier — preserving them for historical integrity without burdening the active retrieval system.

**Inputs:** Memory records with strength < archival threshold (0.15 for routine; governance records never archived); no recent retrieval; no active links to current decisions.

**Process:** Archival is a governed operation — records are not automatically archived; they are flagged for review and formally archived by an authorized process. Archive creates a Memory Archive Entry (MPRIM-023), removes the record from active indices, and retains it in the archive store. If the record has a Preservation Order (MPRIM-015), it cannot be archived regardless of strength.

**Outputs:** Memory Archive Entry (MPRIM-023); record removed from active indices; Preservation Orders respected.

**Timing:** Monthly archival review cycle.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Premature archival: active, important memory archived due to brief period of low retrieval — lost from active use
- Archival without preservation check: record archived despite active Preservation Order
- Archive inaccessibility: archive store not accessible for historical queries — historical memory effectively lost

---

### Stage 24 — Memory Retrieval (on demand)

**Function:** The complete retrieval pipeline — receiving a Retrieval Request (MPRIM-009) from a reasoning agent and delivering the most relevant memories from all applicable tiers.

**Inputs:** Retrieval Request (MPRIM-009) with query parameters, context filters, strength thresholds.

**Process:** Retrieval follows a five-step sequence: (1) index lookup — query each relevant index with the request parameters, (2) candidate scoring — score each candidate memory on relevance, strength, confidence, and context match, (3) threshold filtering — remove candidates below minimum strength and confidence, (4) ranking — order survivors by composite retrieval score, (5) delivery — return the top N records to the requesting agent and create a Recall Event (MPRIM-010). Working memory is checked first — if the requested memory is already loaded, it is returned immediately without index traversal.

**Outputs:** Retrieved memory records delivered to requesting agent; Recall Event (MPRIM-010) logged.

**Timing:** Real-time during decision pipeline — retrieval latency must be < 200ms for working memory, < 2,000ms for long-term.

**Owner Layer:** Layer 17: ControlTower — retrieval engine; Layer 10: DebateAndDecision — primary requester.

**Failure Modes:**
- Retrieval miss: relevant memory not returned due to index gap, threshold too high, or wrong query type
- Retrieval flood: too many results returned — reasoning agent overwhelmed
- Latency breach: retrieval exceeds 2,000ms — decision pipeline stalls

---

### Stage 25 — Memory Version Update (on modification)

**Function:** When a memory record is updated — lesson refined, context corrected, outcome revised — a version record is created and the previous state is preserved.

**Inputs:** Update request with changed fields; current memory record state; update authorization.

**Process:** Before applying any update, Stage 25 creates a Memory Version Record (MPRIM-021) capturing the complete current state of the record. The update is then applied to the live record. The Version Record is linked to the updated record as a prior version. The Provenance Record (MPRIM-024) is updated to append the modification event. The index is updated to reflect changed field values.

**Outputs:** Updated memory record; Version Record (MPRIM-021); updated Provenance Record.

**Timing:** Synchronous with update event.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Version not created before update: prior state lost — rollback impossible
- Provenance not updated: modification not recorded in audit trail — governance failure
- Index not updated after modification: retrieval finds old values — stale retrieval results

---

### Stage 26 — Memory Audit (scheduled)

**Function:** The periodic systematic review of the entire memory system — assessing quality, coverage, decay health, conflict status, governance compliance, and institutional integrity.

**Inputs:** All memory records in all tiers; audit criteria; prior audit results for comparison.

**Process:** The full audit traverses all memory records and assesses: (1) mandatory field completeness for each record, (2) strength distribution (are memories decaying at expected rates?), (3) index coverage (are all records indexed?), (4) conflict resolution status (are all conflicts resolved?), (5) link integrity (do all links point to existing records?), (6) institutional memory completeness (are all required institutional entries present?), (7) constitutional compliance (are MPRIM-025 records current for all institutional entries?). Findings are documented in Memory Audit Records (MPRIM-015). Critical findings trigger immediate remediation.

**Outputs:** Memory Audit Records (MPRIM-015) with findings and remedial actions; quality metrics dashboard update.

**Timing:** Weekly light audit; monthly full audit; annual comprehensive audit.

**Owner Layer:** Layer 17: ControlTower.

**Failure Modes:**
- Incomplete audit scope: some records not reviewed — quality issues persist undetected
- Findings not remediated: audit identifies issues but no action taken within defined SLA
- Audit not conducted on schedule: memory quality degrades without detection

## PART VI — MEMORY ORGANIZATION ARCHITECTURE

### The Living Memory Network

The memory system is not a flat database. It is a living network — a dynamic, multi-dimensional graph in which memories are nodes, associations are edges, clusters are communities, and the entire structure continuously self-organizes in response to the intelligence's evolving experience.

Understanding memory organization is not merely structural knowledge. It is the key to understanding *why* some memories are always readily available while others must be deliberately retrieved, why some memories activate cascades of related content while others stand alone, and why the system can find relevant analogues from years past without explicit search.

### The Five-Tier Memory Hierarchy

```
╔══════════════════════════════════════════════════════════════════╗
║                    MEMORY HIERARCHY                              ║
╠══════════════════════════════════════════════════════════════════╣
║  TIER 1: WORKING MEMORY                                          ║
║  Capacity: ~50 records | Duration: 1 cycle | Speed: immediate   ║
║  Contents: Active decision context, loaded retrievals           ║
╠══════════════════════════════════════════════════════════════════╣
║  TIER 2: SHORT-TERM MEMORY                                       ║
║  Capacity: ~500 records | Duration: 1-30 days | Speed: <200ms   ║
║  Contents: Recent sessions, consolidation queue                 ║
╠══════════════════════════════════════════════════════════════════╣
║  TIER 3: LONG-TERM MEMORY                                        ║
║  Capacity: Unlimited | Duration: indefinite | Speed: <2000ms    ║
║  Contents: Consolidated episodes, patterns, strategies          ║
╠══════════════════════════════════════════════════════════════════╣
║  TIER 4: INSTITUTIONAL MEMORY                                    ║
║  Capacity: ~200 entries | Duration: permanent | Speed: cached   ║
║  Contents: Principles, wisdom, crisis records, governance       ║
╠══════════════════════════════════════════════════════════════════╣
║  TIER 5: ARCHIVE                                                 ║
║  Capacity: Unlimited | Duration: permanent | Speed: <30s        ║
║  Contents: Compressed history, superseded records               ║
╚══════════════════════════════════════════════════════════════════╝
```

### Memory Network Topology

The memory network exhibits a **scale-free topology** — a small number of highly connected hub memories (C-015 Landmarks, I-025 Memory Hubs) and a large number of sparsely connected peripheral memories. This structure has important properties:

**Navigation efficiency:** Any memory can be reached from any other through an average of 6 link traversals (small-world property). This means that even a memory from three years ago in an unrelated domain can be retrieved within 6 associative hops from any current memory.

**Robustness:** The network is robust to the loss of peripheral nodes (individual memories can be deleted or archived without disconnecting the network) but vulnerable to the loss of hub nodes. Hub memories (typically institutional entries, pattern memories, and regime memories) must be protected from decay and must never be archived without creating replacement hubs.

**Emergence:** The network regularly produces emergent insights — memory combinations that were never explicitly linked but whose co-retrieval reveals a relationship not visible in any single memory. This emergent property is the mechanism behind intuitive pattern recognition: many weak associations combine to produce a strong signal.

### Memory Cluster Architecture

Memory clusters are the meso-level organization between individual records and the full network. Each cluster organizes memories sharing a common principle:

| Cluster Type | Organizing Principle | Typical Size | Decay Policy |
|---|---|---|---|
| Entity Cluster | Same instrument or sector | 20–200 records | Follows member decay |
| Regime Cluster | Same market regime | 50–500 records | Slow; regime reuse |
| Strategy Cluster | Same strategy | 20–300 records | Follows strategy lifecycle |
| Temporal Cluster | Same time period | 10–100 records | Standard |
| Pattern Cluster | Same pattern type | 10–50 records | Very slow |
| Crisis Cluster | Same crisis event | 5–50 records | None (permanent) |
| Learning Cluster | Same learning domain | 20–150 records | Very slow |

### Memory Navigation Principles

1. **Context First:** Retrieval always begins with the current context — regime, entity, time — to focus the navigation space before executing full-text or similarity searches.
2. **Hub Priority:** When navigating to a domain, hub memories (highest centrality score in that domain) are the first waypoints — they have the broadest connectivity and are most likely to lead to the target.
3. **Spreading Activation:** After loading a primary memory, activation automatically spreads to linked memories at strength-weighted probability — enabling passive surfacing of relevant related content.
4. **Tier Cascade:** Retrieval queries working memory first, then short-term, then long-term, then institutional — stopping when sufficient relevant content is found.
5. **Analogue Priority:** When reasoning about a novel situation, analogue retrieval (finding the most similar past episode by context match) is given higher priority than general knowledge retrieval.

## PART VII — RECALL, FORGETTING, AND CONSOLIDATION

### The Three Pillars of Memory Dynamics

Memory is not a static store. It is a dynamic system in continuous flux — memories are recalled, reinforced, consolidated, forgotten, and occasionally resurrected. Understanding the three core dynamic processes of memory reveals why memory behaves like a living system rather than a database, and why the architectural choices made about recall, forgetting, and consolidation determine the quality of all future intelligence.

---

### Section 1 — Recall: The Architecture of Memory Retrieval

Recall is not merely "looking something up." In a living memory system, recall is an active, constructive process that changes the memories it touches. Every recall event is also a reinforcement event. Every retrieval is a test of retrieval quality. Every recall that is used in a successful decision leaves the memory stronger and more accessible for future recall.

#### The Five Recall Mechanisms

**1. Directed Recall**
The agent knows what it needs and issues a precise Retrieval Request (MPRIM-009) with explicit parameters: "retrieve all episodic memories of NIFTY sessions following a 2%+ US market decline, with regime = TRENDING_BULL, within the last 24 months." Directed recall is the fastest and most reliable recall mechanism — it produces high-precision results with low latency because the query is well-specified and the indices are efficient. The failure mode is recall blindness: the agent retrieves only what it knows to ask for, missing what it does not know it needs.

**2. Context-Triggered Recall**
The current context activates memories that share contextual similarity without an explicit request. When the regime classifier detects a HIGH_VOLATILITY regime, regime memories for HIGH_VOLATILITY are automatically loaded into working memory. When the entity being analyzed is TATASTEEL, entity-linked memories for TATASTEEL are automatically surfaced. Context-triggered recall is the mechanism behind "expertise" — the system does not need to explicitly ask for relevant memories; its environment activates them. The failure mode is context confusion: wrong context triggers wrong memories.

**3. Spreading Activation Recall**
When a primary memory is recalled (by directed or context-triggered mechanisms), its activation automatically spreads through its links to neighboring memories. A retrieved episodic memory of a NIFTY crash activates: linked regime memories (what regime preceded the crash?), linked pattern memories (what technical patterns preceded it?), linked strategy memories (which strategies lost most?), and linked risk memories (what risk thresholds were triggered?). The pattern of spreading activation is what enables the kind of rich, multi-dimensional reasoning that characterizes expert investment analysis. The failure mode is activation overflow: activation spreads too broadly, filling working memory with marginally relevant content.

**4. Analogical Recall**
The agent retrieves the past memory whose context most closely matches the current situation — even without knowing the specific memory to request. "The current situation feels like something we have seen before — find the closest analogue." The memory system conducts a similarity search across the context space: current regime, current entity conditions, current technical structure, current macro conditions. The memory with the highest context match score is returned as the best analogue. Analogical recall is the mechanism behind the most sophisticated investment reasoning — the ability to say "this is different from all surface appearances, but structurally it resembles the pre-crash conditions of 2008." The failure mode is false analogue: a superficially similar but structurally different memory is returned as the best match.

**5. Free Association Recall**
Unguided traversal of the memory network from a seed memory — used in exploratory analysis when the agent does not know what it is looking for. "Starting from this learning event about a momentum strategy failure — what does the memory network connect to?" Free association recall is the least efficient but the most creative recall mechanism — it is how the system discovers unexpected connections and emergent insights. It is never used in time-sensitive decision pipelines; it is the mechanism of research and retrospective analysis. The failure mode is fruitless wandering: traversal produces no actionable insight despite consuming significant retrieval resources.

#### Recall Quality Metrics

| Metric | Definition | Target |
|---|---|---|
| **Recall Precision** | Proportion of retrieved memories that are genuinely relevant | ≥ 0.80 |
| **Recall Completeness** | Proportion of genuinely relevant memories that were retrieved | ≥ 0.75 |
| **Recall Latency** | Time to retrieve and deliver results | < 2,000ms (long-term) |
| **Recall Confidence** | Average confidence of retrieved memories | ≥ 0.65 |
| **Recall Utilization** | Proportion of retrieved memories that were actually used | ≥ 0.50 |
| **False Positive Rate** | Proportion of retrieved memories that are irrelevant | ≤ 0.20 |
| **Analogue Quality** | Context match score of best analogue returned | ≥ 0.70 |
| **Reinforcement Rate** | Proportion of recalls that trigger reinforcement | Target ≥ 0.40 |

#### The Recall Paradox

The most important memory for a decision is often the hardest to recall. This is the recall paradox: the strongest, most frequently retrieved memories dominate retrieval — they are always readily available. But the rarest, most unusual memories — the ones that encode once-in-a-decade events — are the hardest to recall precisely because they are rarely retrieved, causing their strength to decay. The memory most needed during a black swan event is the one that has been decaying for years because black swans don't happen often.

The architectural solution to the recall paradox is the **Decay-Resistant Memory** designation (J-040): crisis memories, once-in-a-decade event memories, and explicitly designated high-value unusual memories are marked decay-resistant and are therefore always accessible regardless of retrieval frequency. The governance responsibility is to correctly identify and designate which unusual memories deserve this protection.

---

### Section 2 — Forgetting: The Architecture of Graceful Loss

Forgetting is not failure. Forgetting is the mechanism by which intelligence prevents itself from being paralyzed by the weight of every experience it has ever had. A memory system that never forgot anything would be a memory system that treated a trade from five years ago in a completely different market regime as equally relevant as yesterday's lesson. Graceful forgetting is as important to the quality of intelligence as robust recall.

#### Three Types of Forgetting

**1. Automatic Forgetting (Decay)**
The baseline process by which memories whose strength falls below threshold become inaccessible without explicit deletion. Automatic forgetting is calibrated: each memory type has its own decay rate, ensuring that highly volatile routine observations decay within days while principles and lessons persist for years. Automatic forgetting serves the signal-to-noise function: irrelevant, stale, incorrect memories are gradually removed from active retrieval without requiring explicit governance decisions about each one.

*Architectural risk:* If decay rates are miscalibrated, automatic forgetting becomes either too aggressive (valuable memories are lost before their value is recognized) or too passive (stale, incorrect memories persist and continue to influence decisions).

**2. Intentional Forgetting (Governed Deletion)**
The explicit, governance-approved removal of a memory that has been determined to be harmful, incorrect, or actively misleading. Intentional forgetting is never automatic — it requires a formal Intentional Forgetting Protocol: identification of the memory, documentation of the reason for removal, approval by the appropriate governance body, creation of a forgetting record (so the system knows that the memory existed and was intentionally removed), and execution of deletion.

The most important element of intentional forgetting is the forgetting record. A memory that is removed without a trace creates a vulnerability: the same incorrect belief can re-form from future experiences, creating a cycle of false learning and intentional forgetting. The forgetting record prevents this by preserving the lesson that this particular belief was false — even after the belief itself has been removed.

*Architectural risk:* Intentional forgetting governance can be too slow (harmful memories persist while approval is sought) or too permissive (valuable memories are removed inappropriately). The threshold for intentional forgetting must be high: the system should always prefer to quarantine and reduce the weight of a suspect memory rather than delete it.

**3. Catastrophic Forgetting (Failure)**
The unintended, uncontrolled loss of previously consolidated knowledge when new knowledge overwrites it. Catastrophic forgetting is the most dangerous memory failure mode — it is not a governance decision but an architectural failure. It occurs when: (1) a new memory is stored at the same memory address as an existing memory without creating a version record first, (2) a learning update modifies institutional memory without versioning, or (3) a system upgrade fails to migrate existing memory records.

Catastrophic forgetting is prevented by the version record requirement (Stage 25 of the pipeline — MPRIM-021) and by the immutability rules for institutional memory. Every update to an existing memory must create a version record before applying the update. No memory can be overwritten without its prior state being preserved.

#### The Forgetting Governance Rules

| Rule | Description | Who Enforces |
|---|---|---|
| **FGR-01** | No memory may be deleted without a forgetting record | Layer 17: ControlTower |
| **FGR-02** | Institutional memories may not be deleted — only superseded | Layer 17: ControlTower |
| **FGR-03** | Crisis memories may never be deleted | RiskGuardian (Layer 9) |
| **FGR-04** | Intentional forgetting requires documented rationale | Memory Governance |
| **FGR-05** | Forgetting records are permanent — never subject to forgetting | Layer 17: ControlTower |
| **FGR-06** | Any forgetting that affects a live trading position triggers a review | Layer 7: RiskControl |
| **FGR-07** | Catastrophic forgetting events trigger full audit | All layers |
| **FGR-08** | Forgetting thresholds are reviewed quarterly | Learning System |

### Section 3 — Consolidation: The Architecture of Knowledge Crystallization

Consolidation is the process by which transient short-term memory becomes permanent long-term knowledge. It is the most consequential single operation in the memory system — the decision of what to consolidate determines what the system will remember for years.

#### Why Consolidation is Not Automatic

Consolidation is a judgment call, not a mechanical process. Not every experience deserves to persist in long-term memory. The short-term memory tier is deliberately high-volume and low-threshold: everything potentially worth remembering is captured there first. But if everything captured in short-term were automatically promoted to long-term, the long-term store would rapidly fill with noise — diluting the quality of every retrieval and burying the genuinely valuable knowledge under mountains of routine observations.

The consolidation assessment (Stage 17) applies quality criteria to distinguish what should be kept from what should be allowed to decay. The key questions are: Has this memory been retrieved and validated since creation? Is its content accurate and well-attributed? Does it add something not already in long-term memory? Does it meet the minimum quality standards for its type?

#### Consolidation Failure Modes

**Under-consolidation** occurs when the consolidation threshold is set too high — too much valuable knowledge fails the assessment and is discarded. The system's long-term store remains high-quality but thin. The consequence is that the system repeatedly re-learns the same lessons that were previously learned but not consolidated — inefficient learning from experience.

**Over-consolidation** occurs when the threshold is set too low — too much mediocre knowledge is promoted to long-term. The long-term store fills with noise. Retrieval quality degrades as relevant memories are buried under irrelevant ones. The system's reasoning becomes cluttered and imprecise.

**Consolidation timing failure** occurs when the consolidation cycle runs too infrequently — memories that should be consolidated decay in the short-term tier before they reach the assessment cycle. The fix is to increase consolidation frequency or to preserve high-value short-term memories with extended retention.

#### Reconsolidation: Memory Updating Without Loss

When a long-term memory is retrieved and used in active reasoning — particularly when the evidence it encounters in the current cycle differs from what it expected — the memory enters a reconsolidation process. During reconsolidation, the memory becomes temporarily modifiable: its content can be updated with new evidence, its strength can be adjusted, and its links can be revised. After reconsolidation completes (triggered by Stage 25 of the pipeline), the updated memory re-stabilizes at its new state, with a complete version record of the prior state.

Reconsolidation is the mechanism by which long-term knowledge is kept current without being rebuilt from scratch. It is the architectural difference between a system that learns from its past and a system that is imprisoned by it.

### Detailed Failure Analysis — Six Critical Modes

---

#### MFM-03: Attribution Failure

**Classification:** Encoding Failure | **Severity:** Critical | **Frequency:** Common

**Mechanism of Failure**

Attribution failure occurs when a memory record stores the outcome of a decision but incorrectly identifies — or fails to identify — which signals, agents, patterns, or conditions caused that outcome. The memory records what happened, but not why. Or it records a plausible-sounding "why" that is not the true causal explanation.

Attribution failure is common because causal attribution is genuinely difficult. Investment outcomes are multi-causal — a profitable trade may be the result of correct regime identification, correct timing, favorable volatility, FII flow, and pure luck. Attribution failure occurs when only one factor is credited (the most salient one, which may not be the most causally important one) or when credit is assigned based on narrative convenience rather than causal analysis.

**What False Attribution Produces**

When attribution is incorrect, reinforcement is applied to the wrong memories. The signal that did NOT predict correctly is strengthened. The signal that DID predict correctly receives no reinforcement. Over many episodes, the memory system becomes increasingly miscalibrated: the strongest, most frequently retrieved memories are those that happened to be associated with good outcomes by coincidence, while the genuinely predictive signals are gradually decaying from disuse.

This is not a hypothetical risk. It is the mechanism behind most systematic over-performance periods that collapse. A system that attributes success to a strategy that was actually riding a regime gets strong positive reinforcement for that strategy — right up until the regime changes.

**Early Warning Signals**

- Calibration curve begins to diverge from 45-degree line (conviction scores no longer correlate with actual win rates)
- Single agent's recommendations dominate attribution in the Consolidation Records
- Strategy-attributed successes concentrate in one regime type
- Attribution confidence scores across recent Learning Events average below 0.55

**Remediation**

1. Freeze attribution-based reinforcement pending audit
2. Run controlled attribution analysis: decompose outcomes into components using the learning system's counterfactual reasoning
3. Recompute attribution for the most recent 60 learning events
4. Identify systematic attribution bias (which signals are being systematically over-credited)
5. Apply corrective decay to over-reinforced memories
6. Recalibrate the attribution model
7. Add attribution confidence monitoring to weekly audit checklist

---

#### MFM-06: Confidence Overstatement

**Classification:** Quality Failure | **Severity:** Critical | **Frequency:** Common

**Mechanism of Failure**

Confidence overstatement occurs when memory records are assigned confidence values higher than their evidence warrants. A memory that should be rated 0.55 (uncertain, limited evidence) is rated 0.80 (highly confident, strong evidence). The result: when the retrieval system filters by minimum confidence, it returns the overstated-confidence memory as though it is well-validated — and the reasoning agent treats it with a trust level it has not earned.

Confidence overstatement typically accumulates through three mechanisms: (1) initialization error — confidence initialized at the default of the source tier rather than calibrated to the actual evidence, (2) reinforcement without evidence — confidence updated positively when outcomes match predictions, regardless of whether the prediction was genuinely confident or merely lucky, (3) anchor persistence — once a confidence value is assigned, it tends to persist even as the evidence base weakens.

**Why It Is Critical**

In the decision pipeline, the difference between a 0.55-confidence memory and an 0.80-confidence memory is profound. A 0.55 memory influences a decision cautiously — it is one data point among many. A 0.80 memory influences a decision aggressively — it is treated as strong evidence that raises conviction scores and may be sufficient to cross the 6.5/10 decision threshold on its own. Confidence overstatement therefore directly inflates conviction scores, producing more decisions at higher conviction than evidence warrants.

**Early Warning Signals**

- Average confidence across new records exceeds 0.78 (historical baseline 0.65)
- Calibration analysis shows confidence 0.8 memories winning at rate below 0.65
- High-confidence memories retrieved for decisions that subsequently fail at above-expected rates
- Retrieval quality review shows returned memories with confidence 0.75+ that were later found to be incorrect

**Remediation**

1. Audit all records with confidence > 0.75 created in the last 90 days
2. Recalculate confidence from first principles using the source evidence, not the assigned value
3. Apply calibration correction: if records rated 0.80 are winning at 0.60 rate, reduce the confidence by the deviation
4. Recalibrate the confidence initialization algorithm to use evidence-based assignments
5. Implement confidence decay: if a memory has not been validated since creation, decay its confidence at 0.01 per month
6. Add confidence calibration to monthly quality audit

#### MFM-19: False Analogue

**Classification:** Retrieval Failure | **Severity:** Critical | **Frequency:** Occasional

**Mechanism of Failure**

False analogue occurs when the analogue retrieval mechanism (Stage 24, Recall Mechanism 4) returns a past memory as the "best match" for a current situation — when in fact the structural similarity is superficial and the past memory's lessons do not apply to the current situation.

The surface features of two situations can be identical while their deep structures are completely different. NIFTY falling 4% on elevated volume can look the same whether the cause is a global risk-off event (lesson: reduce risk broadly, recovery will be V-shaped) or a sector-specific credit event (lesson: reduce sector exposure, recovery will be slow and uneven). If the analogue retrieval system returns the global risk-off memory when the current situation is a sector credit event, the decisions made from that analogue will be systematically wrong.

**Why It Is Critical**

Analogical reasoning is one of the most powerful tools in the investment intelligence arsenal. When it works correctly, it enables the system to respond to novel situations by applying proven lessons. When it fails — when a false analogue is retrieved with high confidence — the system applies a proven lesson to a situation where it does not apply. The more confident the system is in the false analogue, the more aggressive the incorrect response.

The false analogue failure mode is especially dangerous because it is psychologically compelling. A past episode that superficially resembles the current situation feels like validation, not a risk. The discipline required to evaluate whether the deep structural features match — not just the surface features — is the discipline that protects against false analogue failure.

**Early Warning Signals**

- Analogue matches returned have context similarity scores between 0.65 and 0.75 (borderline) but are being used at 0.90+ confidence
- Decisions supported by analogical reasoning are failing at higher rates than decisions supported by direct evidence
- Analogue quality scores in Recall Events average below 0.70

**Remediation**

1. Require deep context match (not just surface features) for analogue to be used in high-conviction decisions
2. Add a mandatory second dimension of analogue validation: regime must match, not just price pattern
3. Set analogue confidence ceiling at 0.80 unless structural match is confirmed by multi-layer analysis
4. Review recent false analogue cases and extract lessons about which surface features mislead most frequently
5. Implement "analogue challenge" step in the decision debate: one agent must explicitly argue against the analogue before it is accepted

---

#### MFM-21: Catastrophic Forgetting

**Classification:** Decay Failure | **Severity:** Critical | **Frequency:** Rare

**Mechanism of Failure**

Catastrophic forgetting is the complete, unrecoverable loss of a set of previously consolidated memories caused by an overwriting operation, a system upgrade, or a learning update that modifies the underlying memory structure without preserving prior states. Unlike gradual forgetting (a memory's strength decays to zero), catastrophic forgetting is sudden — working knowledge is lost in a single event.

The canonical form occurs in machine learning systems when a model is trained on new data without mechanisms to preserve prior learning — the new training overwrites the old parameters. In the constitutional memory architecture, the equivalent would be: (1) a bulk re-indexing operation that incorrectly overwrites existing index entries, (2) a learning update that applies a parameter change globally without version control, (3) a consolidation failure that deletes short-term memories before long-term transfer is complete, or (4) a storage migration that fails partway through, leaving the system in a split-brain state.

**Why It Is Critical**

Catastrophic forgetting can eliminate years of accumulated institutional knowledge in a single event. If the episode memories from the 2020 COVID crisis are lost, the system loses its institutional knowledge of how markets behave during liquidity crises. If the pattern memories for a specific instrument are lost, the system must relearn from scratch the behavioral characteristics that took years to accumulate. The learning cost is years of new experience — during which the system operates without the full context it once had.

**Early Warning Signals**

- Sudden drop in the count of active memory records without corresponding archival records
- Retrieval queries for historical events return zero results when they previously returned results
- Institutional memory entries no longer appearing in decision contexts where they previously appeared
- System upgrade followed by anomalous behavior in any component that relies on long-term memory

**Remediation**

1. Immediately halt all memory write operations pending diagnosis
2. Inventory the current memory store and compare to the most recent backup snapshot
3. Identify the scope of loss: which records are missing, what time period they covered, what domains
4. Restore from the most recent complete backup snapshot
5. Replay all operations since the backup using the operations log
6. Audit the restored memory for completeness and integrity
7. Implement the change that caused the catastrophic forgetting in a controlled, staged manner with full backup
8. Update the catastrophic forgetting prevention checklist for all future system modifications

#### MFM-28: Memory Conflict Unresolved

**Classification:** Governance Failure | **Severity:** Critical | **Frequency:** Occasional

**Mechanism of Failure**

A memory conflict (two records asserting contradictory information about the same reality) is created as soon as it is detected (MPRIM-014). Resolution is required within a defined SLA — typically 48 hours for routine conflicts, 4 hours for conflicts involving live positions. Memory conflict unresolved occurs when a conflict persists beyond its resolution SLA — meaning that two contradictory beliefs are simultaneously active in the memory network.

The consequence is systematic. When the retrieval system is asked for information in the conflicted domain, it may return either memory, depending on which one ranks higher in the priority ordering at retrieval time. Different queries return different answers to the same question. Agents in the debate system draw on different memories and reach different conclusions not because they are reasoning differently but because they are working from different versions of the same "fact." The debate becomes incoherent.

**Why It Is Critical**

Unresolved conflicts create a fundamentally unreliable memory system. Any system state in which contradictory information can be simultaneously active as high-confidence memory is a state in which the intelligence cannot be trusted to produce consistent outputs. This is not merely a quality concern — it is a correctness concern. An investment system operating with unresolved contradictions in its memory can make opposite decisions about the same situation on different cycles.

**Early Warning Signals**

- Conflict queue has entries older than 48 hours
- Decision variance unexpectedly high: the same market conditions produce different conviction scores across cycles
- Debate agents diverge sharply on factual matters (not on interpretation — on facts)
- Memory Audit Record shows open conflicts at quarterly review

**Remediation**

1. Pull all open conflict records from the conflict queue
2. Prioritize by severity (live position involvement = highest priority)
3. For each conflict: identify which memory is more recent, more strongly evidenced, and more consistent with the broader memory network
4. Apply decay to the losing memory: reduce its strength to below the active retrieval threshold
5. Create a Resolution Record documenting which memory was preserved and why
6. Implement conflict SLA monitoring: alert the governance layer when any conflict exceeds 24 hours unresolved
7. Review the conflict detection mechanism to determine if similar conflicts were missed

#### MFM-32: Memory System Fragmentation

**Classification:** Systemic Failure | **Severity:** Critical | **Frequency:** Rare

**Mechanism of Failure**

Memory system fragmentation occurs when the memory network loses its connected, coherent structure — splitting into isolated regions that cannot communicate with each other. Memories in one region cannot be retrieved in the context of memories in another region; links that were supposed to connect the regions have been broken; the associative network that enables comprehensive, multi-domain reasoning has degenerated into a set of disconnected silos.

Fragmentation accumulates gradually through: (1) link decay without replacement — links between regions decay and are not reinforced because retrievals stay within their home domain, (2) clustering without bridging — the clustering algorithm creates tight, well-cohesive clusters but fails to create cross-cluster bridges, (3) partition over-enforcement — domain-based memory partitions become so strict that inter-domain links cannot be formed, (4) upgrade misalignment — different components of the memory system are updated at different times, creating version incompatibilities that prevent link formation.

**Why It Is Critical**

The most powerful reasoning requires multi-domain synthesis: combining macro memory with technical memory with risk memory with historical episodic memory to reach a conclusion that no single domain could produce alone. Fragmented memory makes this synthesis impossible. Each domain is well-maintained internally but cannot communicate with other domains. The system becomes capable of sophisticated single-domain reasoning but loses the integrative, cross-domain intelligence that characterizes genuine investment wisdom.

**Early Warning Signals**

- Memory network diameter increasing over time (more hops required to traverse from one domain to another)
- Cross-domain retrievals returning fewer results than expected
- Decisions that involve multiple domains showing lower quality than single-domain decisions
- Network topology audit shows clusters with zero inter-cluster bridges
- Spreading activation retrieval reaching boundary of home cluster and stopping

**Remediation**

1. Run full network topology audit: map all clusters, identify inter-cluster link counts
2. Identify fragmented regions: clusters with fewer than 3 inter-cluster bridges
3. Explicitly create bridging links: cross-reference memories that should be connected but aren't (temporal bridges, regime bridges, entity bridges)
4. Implement fragmentation monitoring: track network diameter and inter-cluster connectivity in weekly audit
5. Review link decay policy: inter-cluster links should have lower decay rates than intra-cluster links
6. Schedule quarterly defragmentation runs: identify and heal network regions that are drifting toward isolation

## PART IX — THE MEMORY CONSTITUTION: 40 INVIOLABLE PRINCIPLES

### Constitutional Preamble

These 40 principles are not guidelines. They are not best practices. They are the inviolable rules that govern every memory operation in the AI Trading Brain — from the creation of the most transient Trace to the preservation of the most permanent Institutional Entry. No agent may override these principles. No operational urgency may suspend them. No performance pressure may circumvent them.

The Memory Constitution exists because memory failure is investment failure. A system that compromises its memory principles under pressure will produce unreliable outputs precisely when reliability matters most — in crisis, in novelty, in the moments when the past offers its most important guidance.

Each principle is stated, rationed, and assigned a violation consequence. The violation consequences are not punitive — they are operational: the specific harm that occurs when the principle is violated, making clear why the principle exists.

---

**Principle M-001 — Complete Context**

*Statement:* No memory record may be created without a complete context record (MPRIM-006) capturing the full environmental conditions at the time of the original event.

*Rationale:* A memory without context is a fact without a frame — it can be stated but not interpreted. The system must be able to know not just that something happened, but what the world looked like when it happened. Context is what enables analogical retrieval: matching current conditions to past conditions to find relevant memories.

*Application:* If context data is incomplete at creation time, the Memory Trace may be created and promoted, but it may not be classified above short-term tier until context is populated. Context must be captured at event time — retrospective context is not equivalent.

*Violation Consequence:* Context-free memories cannot support analogical reasoning. Retrieval quality degrades. The system makes decisions based on decontextualized facts, producing systematic errors in novel-but-structurally-familiar situations.

---

**Principle M-002 — Immutable History**

*Statement:* The content of any memory record, as it was at creation or at any prior version, may never be altered retroactively. Updates create new versions; they do not rewrite history.

*Rationale:* Investment intelligence requires honest accounting of what was believed and when it was believed. A system that can rewrite its own past cannot be audited, cannot be calibrated, and cannot be trusted. Immutable history is the foundation of genuine learning: learning requires knowing what you believed before, not only what you believe now.

*Application:* Every update to a memory record must first create a Version Record (MPRIM-021). The prior state is preserved in full. Only new fields or updated fields in the current version reflect the change. No field in any prior version may be modified.

*Violation Consequence:* Retroactive modification makes calibration impossible (you cannot calibrate conviction scores if prior conviction values can be changed after outcomes are known), audit impossible (the audit trail is fabricated), and learning dishonest (you cannot learn from experience if you are rewriting the experience).

---

**Principle M-003 — Narrative Integrity**

*Statement:* Episodic memory entries must preserve the narrative integrity of the events they record — including the sequence, the uncertainty, and the reasoning that existed at the time, not the understanding that came after.

*Rationale:* Hindsight bias is the enemy of episodic learning. If an episode is recorded "after the fact" — with the outcome known, the reasoning retrofitted, and the narrative constructed to make the outcome seem inevitable — the episode becomes useless as training data. The system cannot learn from false narratives.

*Application:* Episodic memory entries must be created using the pre-outcome decision record (from Stage 03) as their foundation. The narrative must reflect the uncertainty that existed at decision time. Post-hoc annotations (lessons, attribution corrections) may be added, but they must be clearly labeled as retrospective.

*Violation Consequence:* Hindsight-contaminated episodic memory produces overconfident future decisions. The system learns that its past decisions were clearer than they were, raising conviction inappropriately.

---

**Principle M-004 — Complete Episodes**

*Statement:* Every identified investment episode must be recorded from beginning to end. A memory system may not capture the opening of an episode without capturing its resolution.

*Rationale:* An episode with only an entry and no exit is not a lesson — it is a suspended question. The learning system requires complete decision-outcome pairs (Stage 03 + Stage 04) to extract any lesson. Incomplete episodes that accumulate in the memory system represent learning opportunities lost.

*Application:* A mechanism must ensure that every opened trade episode, market episode, or learning episode is closed at EOD if not closed earlier. Orphaned open episodes are flagged at each consolidation cycle. An episode older than 30 days without resolution triggers an escalation.

*Violation Consequence:* Incomplete episodes cannot generate reinforcement, cannot generate lessons, and cannot be used for analogical retrieval (an analogue without an outcome is useless). The learning system is systematically deprived of its training data.

---

**Principle M-005 — Attribution Required**

*Statement:* Every memory record of type OUTCOME, LEARNING_EVENT, or LESSON must include a documented attribution: which signals, agents, or conditions caused the outcome.

*Rationale:* An outcome without attribution is a fact without a lesson. Knowing that a trade made 2% is information. Knowing that the trade made 2% because the momentum signal was correct, the regime was favorable, and the entry timing was disciplined is knowledge. Knowledge enables improvement; information alone does not.

*Application:* Attribution is required at creation time. If attribution cannot be determined with confidence ≥ 0.4, the memory is created with partial attribution and an attribution_pending flag. Attribution must be completed within 7 days or the memory is demoted to low confidence.

*Violation Consequence:* Reinforcement without attribution strengthens the wrong memories. The system rewards noise rather than signal. Strategy quality degrades systematically.

---

**Principle M-006 — No Lost Events**

*Statement:* Every significant market event, execution event, decision event, and governance event must create at least a Memory Trace (MPRIM-003) immediately upon detection, even before full processing is available.

*Rationale:* Event-time data is irreplaceable. Once the moment of an event passes, its full context begins to degrade — related data flows past, market conditions shift, and the emotional and behavioral context of the event becomes impossible to reconstruct. The Trace is the minimum viable record that prevents any event from being lost.

*Application:* All signal-producing layers (Layers 2, 6, 9, 10, 11, 12) must create a Trace at event detection time, regardless of downstream processing capacity. Traces are stored in a high-priority queue that is never subject to capacity constraints. Missing Traces are a Severity 1 audit finding.

*Violation Consequence:* Lost events are permanently lost learning opportunities. If a critical risk signal occurs at the wrong moment in the pipeline and no Trace is created, the signal is never encoded — and the same signal in the future goes unrecognized.

---

**Principle M-007 — Temporal Accuracy**

*Statement:* Memory records must use event time (when the event occurred) as the primary timestamp, not processing time (when the memory was created). The distinction must always be preserved.

*Rationale:* Temporal reasoning — understanding sequences, detecting patterns, identifying regime transitions — requires accurate timing of events. If the timestamp in a memory reflects when the system processed the event rather than when the event occurred, temporal analysis will be systematically distorted.

*Application:* All memory records must include both event_time and creation_time as separate mandatory fields. The event_time is used for all temporal reasoning and retrieval. The creation_time is used for pipeline monitoring only.

*Violation Consequence:* Temporal analysis failure. Events that occurred at time T will be retrieved as if they occurred at T+processing_delay. Pattern detection will find false patterns in the delay structure rather than in the actual event sequence.

---

**Principle M-008 — Crisis Preservation**

*Statement:* All memories related to a designated crisis event are permanently preserved at full resolution, without compression, without archival, and without decay. Crisis memory is the most protected memory category.

*Rationale:* Crises are the most valuable learning experiences precisely because they are rare. The lessons from a market crash may not be applicable for years — but when they become applicable, they are critically important. A crisis memory that was compressed to save storage space, or allowed to decay because it was rarely retrieved, may be unavailable precisely when it is most needed.

*Application:* Crisis designation is applied by Layer 9: RiskGuardian. All memories tagged with a crisis event identifier receive the PRESERVE_PERMANENTLY flag. The preservation flag is permanent and cannot be overridden by any automated process.

*Violation Consequence:* The next time conditions similar to a past crisis arise, the system cannot access its memory of how to respond. It improvises under pressure — the worst condition for decision-making.

---

**Principle M-009 — Pattern Validation**

*Statement:* No market pattern may be encoded as a Pattern Memory (MT-09) without validation across a minimum of 3 independent market cycles with statistical confidence ≥ 0.60.

*Rationale:* Pattern recognition is powerful only if the patterns are real. A pattern observed in one market cycle may be a coincidence; a pattern that appears across 3 independent cycles with consistent behavior begins to constitute evidence. Without this standard, the system fills its pattern memory with spurious correlations.

*Application:* Pattern candidates that do not meet the validation standard are stored as Pattern Hypotheses (MT-31 Inference Memory) — retrievable, but flagged as unvalidated. Promotion to Pattern Memory (MT-09) requires formal validation through the Research Lab (Layer 15).

*Violation Consequence:* Spurious pattern memories distort the system's understanding of market structure. Strategies built around spurious patterns perform well in backtests (since the pattern appeared in the data) but fail in live markets (since the pattern was not real).

---

**Principle M-010 — Regime Coverage**

*Statement:* The memory system must maintain active memory records for every regime type classified by the MarketIntelligence layer — including rare and historically unrepeated regime types.

*Rationale:* Regimes that the system has not experienced are regimes for which it has no memory. A system that has only operated in bull markets has no regime memory for bear markets. When the bear market arrives, the system is operating blind. Regime coverage is the commitment to maintaining preparedness across all possible states.

*Application:* An annual regime coverage audit must verify that: each regime type in the MarketIntelligence taxonomy has at least 3 memory records. Missing coverage is addressed through scenario generation (creating synthetic regime memories from principles) and through explicit flagging that a regime is uncharted.

*Violation Consequence:* When an uncovered regime occurs, the system has no analogous memory to draw on. It cannot identify the best strategy, cannot calibrate conviction appropriately, and cannot anticipate how conditions will evolve.

---

**Principle M-011 — Retrieval Speed**

*Statement:* Memory retrieval latency must not cause pipeline stalls. Working memory access must complete within 50ms; long-term retrieval within 2,000ms; institutional retrieval within 500ms.

*Rationale:* Memory that cannot be retrieved within the decision pipeline's timing constraints is effectively unavailable. A brilliant analysis that arrives after the decision has been committed is useless. Memory architecture must be designed around retrieval speed as a primary constraint.

*Application:* Retrieval latency is monitored in every Recall Event (MPRIM-010). Breaches are flagged immediately. Recurring latency breach for a specific memory type triggers architecture review. Institutional memories are pre-loaded into a warm cache at session start.

*Violation Consequence:* Decision pipeline stalls. Either the decision proceeds without the missing memory (blind decision) or the pipeline blocks waiting for retrieval (missed market opportunity).

---

**Principle M-012 — Context Immutability**

*Statement:* The context record (MPRIM-006) of a memory is immutable after creation. It may only be annotated with retrospective observations, never modified.

*Rationale:* The context is the environmental record of a specific moment in time. That moment cannot be changed. If the context is modifiable, the record of what conditions existed at event time becomes unreliable — and analogical retrieval (which matches current conditions to past contexts) becomes invalid.

*Application:* All write operations to context records after creation are rejected except for the retrospective_annotations field, which is append-only. Modification attempts are logged as policy violations.

*Violation Consequence:* Modified contexts corrupt analogical retrieval. The system will retrieve memories as if they occurred in different conditions than they actually did — producing systematically wrong analogies.

---

**Principle M-013 — Context Fidelity**

*Statement:* Context records must accurately represent the conditions that existed at the time of the event, not the conditions at the time of encoding. When these differ, both must be recorded with clear labels.

*Rationale:* Encoding latency creates a gap: the conditions at encoding time may differ from the conditions at event time. If this gap is not explicitly recorded, memories appear to have been created in conditions that did not apply. Temporal reasoning and pattern detection will both be distorted.

*Application:* Market snapshots for context creation are taken at event time and stored in a temporary buffer. If processing delay exceeds 60 seconds, both event-time snapshot and encoding-time snapshot are recorded. The event-time snapshot is used for temporal reasoning; the encoding-time snapshot is logged for pipeline monitoring.

*Violation Consequence:* All temporal reasoning is distorted by the average encoding latency. Pattern detection finds artifacts of the encoding process rather than genuine market patterns.

---

**Principle M-014 — Link Validity**

*Statement:* Memory links (MPRIM-007) must represent genuine relationships. False associations — links formed by coincidence, algorithmic artifact, or incorrect reasoning — must be identified and removed.

*Rationale:* A memory network built on false links is a reasoning network built on false premises. Spreading activation through false links surfaces irrelevant memories. Analogical reasoning along false associations reaches wrong analogues. The quality of every link is a component of the quality of the network.

*Application:* Link validity is assessed at two points: at creation (each new link must meet a minimum evidence standard for its link type) and at audit (existing links are reviewed against the records they connect). Links whose endpoints have diverged in meaning are flagged for review.

*Violation Consequence:* False associations produce false reasoning. The system retrieves memories that seem relevant (because they are linked to a query anchor) but actually contain misleading information. Decision quality degrades without an obvious failure signal.

---

**Principle M-015 — Association Governance**

*Statement:* The creation of new memory links, particularly associative and causal links, must be governed by a minimum evidence standard. Not every co-occurrence is an association; not every sequence is a cause.

*Rationale:* The distinction between correlation and causation is the most consequential distinction in investment analysis. A memory link that encodes a causal relationship when the relationship is merely correlational will be used in causal reasoning — producing systematically incorrect predictions about what will happen when conditions change.

*Application:* Causal links require a documented causal mechanism — not merely temporal proximity. New causal links are created only by the Learning System (Layer 13) or the Research Lab (Layer 15), not by automated association algorithms. Correlational links are created automatically but are clearly labeled as correlational, not causal.

*Violation Consequence:* Causal reasoning built on correlational links produces predictions that are valid only as long as the correlation holds — and correlations in investment markets change without warning.

---

**Principle M-016 — Snapshot Completeness**

*Statement:* Memory snapshots (MPRIM-008) created at scheduled or event-triggered intervals must achieve a completeness score ≥ 0.90 before being accepted. Incomplete snapshots are supplemented or rejected.

*Rationale:* A snapshot that captures 80% of the memory domain is not a reliable baseline — the 20% gap may be exactly the content that changes between snapshots and matters for comparison. Completeness is the minimum acceptable standard for a record that will be used as a historical benchmark.

*Application:* The snapshot engine verifies completeness after creation. If completeness < 0.90, the engine runs a supplemental pass to capture the missing records. If the second pass still fails to achieve 0.90, the snapshot is flagged as INCOMPLETE and must not be used as a baseline.

*Violation Consequence:* Comparisons made against an incomplete snapshot will produce false deltas — changes will appear where there are none (because the prior snapshot missed records that now appear different) and real changes will be missed (because the affected records were not captured).

---

**Principle M-017 — Retrieval Explicitness**

*Statement:* Every memory retrieval must be initiated through a formal Retrieval Request (MPRIM-009) with all mandatory fields populated. Implicit or undocumented retrieval is not permitted.

*Rationale:* Undocumented retrieval is unreviewable retrieval. If an agent accesses memory without creating a Retrieval Request, there is no audit trail, no quality metric, no reinforcement trigger, and no basis for improvement. The discipline of explicit retrieval requests is the discipline of auditable intelligence.

*Application:* All 17 layers must route memory access through the standard retrieval API, which requires a Retrieval Request object. Direct memory access that bypasses the API is a Severity 1 governance violation.

*Violation Consequence:* Unaudited retrieval produces decisions that cannot be fully explained. When a decision fails, the analysis cannot determine which memories were retrieved — the audit trail is incomplete. System improvement is hindered.

---

**Principle M-018 — Purpose Documentation**

*Statement:* Every Retrieval Request (MPRIM-009) must include a documented purpose field: why is this memory being retrieved, and for what decision does the requester intend to use it?

*Rationale:* Purpose documentation enables post-hoc analysis of retrieval quality. If a retrieval is made for purpose "analogical reasoning for NIFTY position decision" and the retrieved memory turns out to be irrelevant, the purpose field enables diagnosis of whether the retrieval query was wrong or the index was incorrect.

*Application:* The purpose field is a mandatory field in MPRIM-009. Retrieval Requests with empty or vague purpose fields ("general context") are accepted but generate a quality flag.

*Violation Consequence:* Without purpose documentation, retrieval quality analysis cannot determine whether retrievals are serving their intended function. Improvement of the retrieval mechanism is impossible without this feedback.

---

**Principle M-019 — Complete Audit Trail**

*Statement:* Every memory creation, modification, retrieval, consolidation, decay, archival, and deletion event must generate a log entry. The audit trail is complete and perpetual.

*Rationale:* Memory governance requires visibility. Without a complete audit trail, governance decisions cannot be reviewed, errors cannot be diagnosed, and improvements cannot be validated. The audit trail is the instrument of institutional accountability for memory management.

*Application:* All memory pipeline stages (01 through 26) generate log entries as a mandatory output. Log entries are stored in a separate, protected audit store that is not subject to the memory system's own decay or archival policies.

*Violation Consequence:* Without an audit trail, every memory governance decision becomes unverifiable. The institution cannot demonstrate that its memory is well-governed, cannot diagnose systematic errors, and cannot comply with its own governance standards.

---

**Principle M-020 — Retrieval Accountability**

*Statement:* The quality of every memory retrieval must be tracked: what was retrieved, whether it was relevant, and whether it contributed to a correct or incorrect decision.

*Rationale:* Retrieval accountability is the feedback loop that enables the memory system to improve. If retrievals are not evaluated against their outcomes, the retrieval algorithm cannot be calibrated, the index structure cannot be optimized, and the decay model cannot be validated.

*Application:* Recall Events (MPRIM-010) must include use_outcome where available. The Learning System must close the loop between retrieval and outcome within one consolidation cycle.

*Violation Consequence:* The memory system cannot improve its retrieval quality without this feedback. Systematic retrieval failures persist uncorrected.

---

**Principle M-021 — Consolidation Accountability**

*Statement:* Every consolidation decision — whether to promote, defer, or discard a short-term memory — must be documented in a Memory Consolidation Record (MPRIM-011) with the rationale for the decision.

*Rationale:* Consolidation decisions determine the long-term knowledge base. They are among the most consequential decisions the memory system makes. Undocumented consolidation decisions cannot be reviewed, appealed, or learned from.

*Application:* No consolidation action may be taken without first creating the Consolidation Record. The record is created before the action, not after.

*Violation Consequence:* Valuable memories are discarded without accountability. When learning gaps emerge — the system repeatedly makes the same mistake because it does not remember a prior correction — there is no record to diagnose why the correcting memory was not consolidated.

---

**Principle M-022 — Discard Governance**

*Statement:* No memory may be permanently discarded (deleted from all tiers including archive) without explicit governance approval. The discard decision must be documented with rationale.

*Rationale:* Permanent deletion is irreversible. A memory that is incorrectly discarded is permanently gone. The threshold for permanent deletion must therefore be very high, and the governance process very deliberate.

*Application:* Deletion requires: (1) the memory has been in archive for ≥ the retention period for its type, (2) the memory has no active references from live decision or learning records, (3) the memory does not have a Preservation Order, (4) an authorized governance layer has reviewed and approved the deletion. Automated deletion is not permitted.

*Violation Consequence:* Incorrectly deleted memories create permanent learning gaps. The system has no recovery path.

---

**Principle M-023 — Decay Monitoring**

*Statement:* Memory decay rates must be actively monitored. Unexpected decay patterns (memories decaying faster or slower than calibrated) are an audit finding requiring investigation.

*Rationale:* Decay calibration is not a one-time setup — it is an ongoing responsibility. Markets change. The relevance of different memory types changes. A decay rate that was appropriate in one market structure may be inappropriate in another.

*Application:* The weekly audit reviews the distribution of memory strengths across all types. Any type whose average decay rate differs from its calibrated rate by > 20% triggers a decay model review.

*Violation Consequence:* Miscalibrated decay produces either memory hoarding (stale content persisting) or memory starvation (valuable content lost prematurely). Both states degrade decision quality.

---

**Principle M-024 — Decay Calibration**

*Statement:* Decay rates must be calibrated empirically from retrieval data — not set by theoretical assumption. Rates must be reviewed quarterly and adjusted based on observed retrieval patterns.

*Rationale:* Theoretical decay rates are starting assumptions, not validated parameters. The actual rate at which different memory types remain relevant depends on market structure, which changes. Empirical calibration is the only way to keep decay rates aligned with actual relevance patterns.

*Application:* The quarterly decay calibration uses the Recall Event log: for each memory type, what is the average age of memories that are retrieved and used successfully? The decay rate should be set so that the average useful memory still has strength ≥ 0.50 at its average retrieved age.

*Violation Consequence:* Uncalibrated decay produces systematic retrieval bias: the retrieval system favors memories based on their age pattern rather than their actual relevance.

---

**Principle M-025 — Reinforcement Integrity**

*Statement:* Reinforcement must be applied only when there is clear evidence that the reinforced memory contributed to a correct outcome. Reinforcement based on outcome coincidence, on narrative attribution, or on wish rather than evidence is a governance violation.

*Rationale:* Reinforcement is the primary mechanism by which the memory system learns what knowledge is valuable. If reinforcement is applied incorrectly — to memories that did not actually contribute to the outcome — the memory system learns the wrong lesson. Reinforcement integrity is the foundation of learning integrity.

*Application:* All reinforcement events (MPRIM-013) must include an attribution_confidence score. Reinforcement is applied in full only when attribution_confidence ≥ 0.70. For attribution_confidence between 0.40 and 0.70, partial reinforcement is applied at the confidence fraction. Below 0.40, reinforcement is deferred pending investigation.

*Violation Consequence:* Systematically misattributed reinforcement creates a memory network in which the most strongly held beliefs are those that happen to coincide with positive outcomes — regardless of causal validity. This is the mechanism behind overconfidence and strategy fragility.

---

**Principle M-026 — Attribution Correctness**

*Statement:* Attribution analysis must consider all contributing factors — signal quality, timing, regime alignment, risk management, and execution quality — not only the most salient or most recently discussed factor.

*Rationale:* Salient attribution is easy attribution. When a trade succeeds, the most memorable signal gets the credit. When a trade fails, the most recent decision gets the blame. In both cases, other contributing factors are overlooked. Complete attribution requires deliberate enumeration of all contributing factors and their relative importance.

*Application:* Attribution templates for the most common memory types (trade memory, learning event, pattern confirmation) enumerate the factors that must be considered. An attribution that does not address all enumerated factors for a memory type is flagged as incomplete.

*Violation Consequence:* Incomplete attribution produces learning that focuses improvement efforts on the most visible factors while ignoring equally important but less salient ones.

---

**Principle M-027 — Conflict Detection**

*Statement:* The memory system must actively monitor for conflicts between memory records. Passive conflict detection (waiting for a retrieval to surface a contradiction) is insufficient.

*Rationale:* A conflict between two memories that are retrieved in different contexts may never be surfaced by routine retrieval. The two contradictory beliefs can coexist for months without being confronted. Active conflict detection — comparing new memories against existing memories on key dimensions — is the only reliable way to catch conflicts before they cause decision errors.

*Application:* Every new memory creation triggers a conflict check against the most closely related existing memories (within same entity, same regime, same memory type). Conflict check latency must be ≤ 500ms.

*Violation Consequence:* Undetected conflicts coexist silently and produce inconsistent decisions. The same situation may produce different conviction scores on different cycles because different conflicting memories are retrieved on different days.

---

**Principle M-028 — Resolution Governance**

*Statement:* All detected memory conflicts must be resolved within their assigned SLA. Critical conflicts (affecting live positions) within 4 hours. Standard conflicts within 48 hours. Low-severity conflicts within 7 days.

*Rationale:* An unresolved conflict is an open wound in the memory network. Every retrieval in the conflicted domain produces potentially contradictory results. The longer a conflict persists, the more decisions it contaminates.

*Application:* Conflict SLAs are enforced by an automated alert system: conflicts approaching their SLA trigger escalating notifications. Conflicts that breach their SLA trigger an automatic escalation to governance review.

*Violation Consequence:* Contradictory beliefs remain simultaneously active. Decision quality in the conflicted domain becomes unreliable.

---

**Principle M-029 — Audit Completeness**

*Statement:* Memory audits must cover 100% of the institutional memory tier in each monthly audit, 100% of long-term memory in each quarterly audit, and a representative sample (≥25%) of short-term memory in each weekly audit.

*Rationale:* An audit that covers only the easiest or most accessible records is not an audit — it is a cosmetic exercise. Complete coverage is required to ensure that quality problems in any part of the memory system are detected within the audit cycle.

*Application:* Audit coverage metrics are mandatory fields in Memory Audit Records. An audit with coverage below the required thresholds is classified as INCOMPLETE and must be supplemented before the next scheduled audit.

*Violation Consequence:* Incomplete audits allow quality degradation to persist in un-audited regions. By the time the problem is discovered, it may have propagated across the network.

---

**Principle M-030 — Audit Independence**

*Statement:* The agent conducting a memory audit must not be the same agent that created or manages the memories being audited. Audit independence is required for all quarterly and annual audits.

*Rationale:* Self-auditing produces systematically biased results. An agent that creates memories will find it difficult to objectively assess the quality of those memories. Independence ensures that the audit surfaces problems that self-assessment would miss.

*Application:* Audit assignments are made by Layer 17 (ControlTower) using a rotation schedule that ensures no layer audits its own memory records for more than two consecutive audit cycles.

*Violation Consequence:* Self-auditing produces audits that confirm what the auditing agent believes is true, rather than discovering what is actually true. Quality problems in the auditing agent's own records go undetected.

## PART X — THE FUTURE EVOLUTION OF MEMORY

### Where Memory Is Going

The 26 pipeline stages, the 25 primitives, and the 63 governance principles defined in this document represent the architecture of memory as it should be built — the fully realized vision of what a living intelligence's memory can be. But architecture is not implementation. The full vision requires incremental realization, and this Part describes the evolutionary path forward.

The AI Trading Brain's memory architecture will evolve through four developmental phases:

---

### Phase Alpha: Foundations (Operational Now)

The current operational state of the memory system includes:
- Working memory: decision context loaded per cycle through the existing orchestrator
- Short-term memory: per-session state in StrategyPerformanceTracker and MarketMonitor
- Long-term memory: SQLite databases (strategy performance, trade history, pattern records)
- Institutional memory: configuration files, hardcoded principles, strategy constraints
- Basic retrieval: direct SQL queries to the SQLite stores
- Basic decay: time-weighted performance statistics with rolling windows
- Basic consolidation: daily EOD updates to strategy performance metrics

This foundation implements the most critical memory functions — enough to support paper trading and early live trading. What it lacks: associative retrieval, spreading activation, formal context records, conflict detection, and the full governance framework.

**Evolution trigger for next phase:** Live trading for 90 days with stable performance.

---

### Phase Beta: Connected Memory (Next 6 Months)

Phase Beta adds associative memory to the foundation:
- **Explicit memory graph:** Memories stored with link records, enabling traversal queries
- **Context records:** Full MPRIM-006 context capture at every memory creation
- **Regime-tagged retrieval:** All stored records tagged with regime at creation; retrievals filtered by current regime
- **Conflict detection:** Automated check when new learning events contradict existing pattern memories
- **Episode construction:** Formal episode assembly at trade closure (assembling Trade Trace → Entry Record → Monitoring Records → Exit Record → Outcome Record → Lesson into a single Episode)
- **Reinforcement tracking:** Reinforcement applied to pattern memories when patterns are confirmed

This phase realizes the core promise of memory as a living network rather than a collection of tables.

**Evolution trigger:** Memory network connectivity > 3 links per record on average; retrieval precision > 0.75.

---

### Phase Gamma: Institutional Memory (Months 6-18)

Phase Gamma formalizes what the system has learned across its operational lifetime:
- **Institutional memory entries:** Formal review and encoding of the most important lessons from Phase Alpha and Beta
- **Constitutional compliance records:** MPRIM-025 compliance tracking begins for all institutional operations
- **Memory audit cadence:** Weekly light audit, monthly full audit — with documented findings and remediation
- **Semantic memory promotion:** Patterns validated across 3 regimes promoted from episodic to semantic memory
- **Crisis memory vault:** Crisis periods from Phase Alpha and Beta retrospectively encoded with full detail
- **Calibration memory:** Conviction score calibration history formally tracked as memory

This phase is where the system begins to accumulate genuine institutional wisdom — the kind that survives agent upgrades, strategy retirements, and regime changes.

**Evolution trigger:** Institutional memory count > 50 entries; semantic memory count > 100 entries; calibration curve R² > 0.75.

---

### Phase Delta: Full Constitutional Memory (Months 18-36)

Phase Delta implements the complete constitutional vision:
- **Full 26-stage pipeline:** All stages implemented with complete tracking and audit trail
- **Full 25-primitive implementation:** All MPRIM types in active use
- **Spreading activation:** Recall of one memory automatically surfaces linked memories
- **Analogical retrieval:** Context-based search for historical analogues to current situations
- **Memory health dashboard:** Real-time display of memory tier health, decay rates, retrieval quality
- **Automated conflict resolution:** Conflict detection and resolution within SLA
- **Complete governance framework:** All 63 governance principles operationally enforced

At Phase Delta completion, the AI Trading Brain will possess a fully constitutional memory architecture — one that can be audited, improved, and trusted as the foundation of genuine investment intelligence.

**Evolution trigger:** All 63 governance principles operationally verified; memory audit consistently passing at ≥95% quality score.

---

### The Open Questions of Memory Architecture

The architecture defined in this document is complete — but it is not final. Intelligence is a moving target. As the AI Trading Brain accumulates experience, several open questions will require answers that cannot be predetermined:

**Q1: How much context is enough?**
The document specifies a minimum of 5 context fields per memory. Experience will reveal whether 5 is too few (retrieved analogues fail because context is too thin to distinguish similar but different situations) or too many (context capture overhead slows the pipeline). The right number will emerge from retrieval quality data.

**Q2: What is the optimal decay rate for each memory type?**
The decay rates specified in this document are initial calibrations based on theoretical considerations. They will be empirically revised through Phase Beta as retrieval quality data accumulates. The target is to calibrate each type's decay rate so that the average successfully retrieved memory has strength ≥ 0.50 at retrieval time — meaning it has not decayed past the point of reliable use.

**Q3: When does an episodic lesson become a semantic principle?**
The threshold of 5 validating episodes from 2 independent regimes is a starting point. Experience may reveal that some types of patterns require more episodes (complex, multi-factor patterns) while others require fewer (simple, highly reliable patterns in specific instruments). The threshold should be calibrated by pattern type rather than applied universally.

**Q4: How should memory interact with the debate architecture?**
The current design has each of the 5 debate agents drawing from the same shared working memory. An alternative is agent-specific memory subsets — each agent retrieves from memory based on its specific role (Bull Agent retrieves bullish analogues; Bear Agent retrieves bearish analogues). This specialized memory retrieval may produce richer, more internally consistent debate contributions. It is an open architectural question.

**Q5: What is the appropriate institutional memory governance structure?**
The current design requires "multi-layer review" for institutional memory creation without specifying which layers and how many agents must approve. Experience will reveal the right governance threshold — too few approvers risk premature institutionalization; too many risk governance paralysis.

---

### The Memory Singularity

The terminal vision of this memory architecture is what we call the Memory Singularity: the state in which the intelligence system's memory is sufficiently complete, accurate, and well-integrated that it can answer any question about its own investment history, reasoning, and learning with full attribution, complete context, and verified provenance.

At the Memory Singularity, there are no learning gaps — every experience is encoded. There is no recall blindness — every relevant memory surfaces when needed. There is no false attribution — every outcome is correctly assigned to its causes. There is no institutional amnesia — every lesson that has ever been extracted is available to inform every future decision.

The Memory Singularity is not a destination that will be reached in 36 months. It is a direction. Each phase of evolution moves the system toward it. Each principle enforced makes it closer. Each memory correctly created, consolidated, reinforced, and recalled is one step along the path.

Intelligence without memory is perception without understanding. Memory without architecture is history without learning. The AI Trading Brain is built on the conviction that the path to great investment decisions runs through great memory — not through faster computation or more signals, but through the discipline of knowing what has been learned, from what experience, with what confidence, and for what purpose.

### The Memory Integration Promise

Every layer of the AI Trading Brain exists in relationship to memory. No layer operates in isolation from the accumulated knowledge of the system. A layer that cannot access relevant memory is a layer that must reason from scratch — repeating the work of accumulation that prior cycles have already done. A layer that writes to memory without governance creates knowledge pollution that propagates through the network to contaminate every subsequent retrieval.

The integration map above is not merely a technical specification. It is a governance document. It defines which layers are responsible for which memory domains, which reads must be available within what latency, and which writes must comply with which governance standards. Every failure in memory integration is traceable to a specific layer, a specific memory type, and a specific principle in the Memory Constitution.

The AI Trading Brain's memory is not a shared database. It is a shared nervous system — and the health of every layer depends on the health of the memory that connects them all.
