## 1. EB001 Verification

### 1.1 Exact Signatures — Both Sides

**`OrderManager._broker_place()` call** (`execution_engine/order_manager.py` line 1951):

```python
return self._broker.place_order(
    symbol=symbol,            # ← WRONG: kwarg name not accepted by DhanBroker
    exchange="NSE",           # ← WRONG: kwarg name not accepted by DhanBroker
                              #         AND "NSE" is not a valid exchange_segment value
    transaction_type=direction,
    quantity=qty,
    price=price,
    order_type=order_type,
)
```

**`DhanBroker.place_order()` signature** (`execution_engine/brokers/dhan_broker.py` line 51):

```python
def place_order(self, security_id: str, exchange_segment: str,
                transaction_type: str, quantity: int,
                price: float = 0.0, order_type: str = "MARKET",
                product_type: str = "INTRADAY") -> Optional[str]:
```

### 1.2 Mismatch Table

| Position | `_broker_place` sends | `DhanBroker.place_order` expects |
|---|---|---|
| 1st positional | `symbol=symbol` | `security_id` |
| 2nd positional | `exchange="NSE"` | `exchange_segment` |
| 3rd | `transaction_type=direction` ✓ | `transaction_type` ✓ |
| 4th | `quantity=qty` ✓ | `quantity` ✓ |
| 5th | `price=price` ✓ | `price` ✓ |
| 6th | `order_type=order_type` ✓ | `order_type` ✓ |
| 7th | *(not sent)* | `product_type` (default `"INTRADAY"`) |

### 1.3 Defect Confirmed

Python validates keyword argument names at call time, before any function body executes. `DhanBroker.place_order()` has no parameter named `symbol` or `exchange`. Python raises:

```
TypeError: DhanBroker.place_order() got an unexpected keyword argument 'symbol'
```

This fires even when `self._connected = False` (simulation mode), because the TypeError is raised in the calling frame by Python's argument-resolution machinery — before the first line of `place_order()` runs.

**Additional defect in the value**: Even if the kwarg name were corrected, the value `exchange="NSE"` would still be wrong. Dhan's API uses segment identifiers like `"NSE_EQ"` (NSE cash equity), `"NSE_FNO"` (futures and options), `"IDX_I"` (index). The bare string `"NSE"` is not a valid `exchange_segment` value.

## 2. EB002 Verification

### 2.1 Current State

`_broker_place()` currently passes the raw `symbol` string (e.g., `"RELIANCE"`) as the first argument. Dhan's API requires a numeric string `security_id` (e.g., `"2885"` for RELIANCE). There is no translation in `_broker_place()` or anywhere in the execution path between `OrderManager.execute()` and `DhanBroker.place_order()`.

### 2.2 Symbol Mapping Requirement

Dhan's REST API identifies instruments by `(security_id, exchange_segment)` pairs. The `security_id` is a unique integer string assigned by Dhan per instrument. The same integer can appear in different exchange segments (e.g., `"25"` = BANKNIFTY in `IDX_I` AND ADANIENT in `NSE_EQ` — the segment is the disambiguator).

## 6. Failure Handling Assessment

### 6.1 Exception Type and Capture

The TypeError is a Python interpreter error. It is raised before `DhanBroker.place_order()` executes any code. The `try/except Exception as exc` in `_place_entry_with_retry()` (line 1912) catches it:

```python
except Exception as exc:
    log.error("[OrderManager] Attempt %d/%d exception for %s: %s",
              attempt, MAX_ORDER_RETRIES, sig.symbol, exc)
```

- **Logged at ERROR level** — the log message IS written
- **Retry count:** 3 attempts (all fail identically — TypeError is deterministic)
- **Sleep between retries:** 0.5 s + 1.0 s = 1.5 s total wasted on retries
- **Final return:** `None`

### 6.2 Telemetry Visibility

| Layer | What happens | Observable? |
|---|---|---|
| `log.error` | Written to log file | YES — visible in logs |
| `execute()` returns None | Signal silently discarded | ONLY if logs are checked |
| `ORDER_PLACED` event | Never published | trades_executed=0 in CT |
| `EXECUTION_FAILED` event | No such event type defined | INVISIBLE in telemetry |
| `trades_executed` CT column | Stays 0 | YES — visible but not alarmed |

**Assessment:** The failure is semi-visible. The ERROR log message IS written 3 times per failed signal. However, there is no dedicated `EXECUTION_FAILED` EventType — a monitoring agent would need to parse raw log text or observe `trades_executed=0` for multiple cycles to detect the issue. No alarm fires on persistent execution failure.

### 6.3 Whether Fail-Fast Is Better

The current behavior — catching TypeError and retrying — is architecturally incorrect. TypeError is a programming error (wrong API call), not a transient broker failure. Retrying it is wasteful (1.5 s delay, 3 log writes) and misleading. After the fix, the TypeError will disappear, but a new fail-fast for `MISSING_DHAN_MAPPING` is appropriate: if a symbol is not in `DHAN_SECURITY_MAP`, no retry should occur (the symbol won't be added between retries).

**Recommendation (for implementation phase):** The `MISSING_DHAN_MAPPING` case should return `None` immediately from `_broker_place()`, short-circuiting all retries. A single ERROR log with `[MISSING_DHAN_MAPPING]` is sufficient.

## 7. Secondary Defect: Missing `place_sl_order` (DEFECT-EB003)

`OrderManager._place_stop_loss()` calls:

```python
if hasattr(self._broker, "place_sl_order"):
    return self._broker.place_sl_order(...)
```

`DhanBroker` has no `place_sl_order` method (only `place_order`, `cancel_order`, `get_positions`, `get_portfolio`). Therefore `hasattr()` returns `False` and `_place_stop_loss()` returns `None` for all live orders.

**Impact:** After the EB001/EB002 fix, entry orders will reach Dhan, but stop-loss orders will NOT be sent to the broker. Positions will have no exchange-side stop-loss. Risk management relies entirely on the software TradeMonitor loop.

**This defect is documented here but is OUT OF SCOPE for the EB001/EB002 fix.** It requires a separate decision on whether to add `place_sl_order` to `DhanBroker` or to route SL orders through `place_order` with `order_type="STOP_LOSS"`.

## 8. Exact Proposed Fix

### 8.1 Architecture

```
TradeSignal.symbol  (e.g. "RELIANCE")
        ↓
_broker_place() — PROPOSED NEW LOGIC:
  1. If _broker is None → SIM path (unchanged)
  2. Look up symbol in DHAN_SECURITY_MAP (existing authoritative source)
  3. If not found → log [MISSING_DHAN_MAPPING] → return None (fail-fast)
  4. Pass security_id + exchange_segment → DhanBroker.place_order()
        ↓
DhanBroker.place_order(
    security_id      = "2885",    ← correct kwarg, numeric Dhan ID
    exchange_segment = "NSE_EQ",  ← correct kwarg, valid segment value
    transaction_type = "BUY",
    quantity         = 1,
    price            = 1320.0,
    order_type       = "LIMIT",
)
```

### 8.2 Proposed Patch — `_broker_place()` body only

**File:** `execution_engine/order_manager.py`  
**Method:** `_broker_place()`  
**Current lines:** 1942–1955 (14 lines)  
**Proposed lines:** ~25 lines  
**Interface change:** None — signature unchanged

```python
def _broker_place(self, symbol: str, direction: str,
                   qty: int, price: float,
                   order_type: str = "LIMIT") -> Optional[str]:
    if not self._broker:
        log.info("[OrderManager] [SIM-%s] %s %s qty=%d @ %.2f",
                 order_type, direction, symbol, qty, price)
        import time as _t
        _ms = _t.time_ns() // 1_000_000
        return f"SIM_{symbol}_{direction}_Q{qty}_P{price:.2f}_{_ms}"
    # Resolve NSE ticker → Dhan (security_id, exchange_segment)
    from data_feeds.dhan_feed import DHAN_SECURITY_MAP as _DSM
    _sym = symbol.upper().replace(".NS", "").replace(".BO", "")
    _meta = _DSM.get(_sym)
    if not _meta:
        log.error(
            "[OrderManager] [MISSING_DHAN_MAPPING] symbol=%s not in DHAN_SECURITY_MAP"
            " — order blocked. Add entry to data_feeds/dhan_feed.py.",
            symbol,
        )
        return None
    return self._broker.place_order(
        security_id      = _meta["security_id"],
        exchange_segment = _meta["segment"],
        transaction_type = direction,
        quantity         = qty,
        price            = price,
        order_type       = order_type,
    )
```
