## 1. Executive Verdict

The system has a CRITICAL defect that renders the entire historical bootstrap subsystem inoperative for knowledge-driven trading decisions. The 1,170 OutcomeRecords generated by KBS-001 are injected into the wrong HBE instance — a module-level singleton — while the KnowledgeDecisionPipeline creates and uses a completely separate HBE instance loaded from KLP disk files. The records never reach KDA.

**The answer to the most important final question:**

> "Can this system now use the 1,170 historically bootstrapped outcomes to produce useful knowledge that can influence today's live trading decisions?"

**NO. The causal chain is broken. This is proven experimentally in Phase 3.**

Three additional medium/low defects were found. No financial safety defects exist (paper trading is safe). The system should NOT be moved to live trading until D016-001 is fixed and verified.

## 4. Phase 2 — Historical Bootstrap Audit

### A. Source data
- **Date range**: up to 365 calendar days before bootstrap run date
- **Symbols**: 37 hardcoded NSE symbols across 8 sectors
- **Provider**: yfinance (auto_adjust=True, timeout=8)
- **OHLCV fields used**: Open, High, Low, Close (Volume not used)
- **Missing bars**: `len(closes) < _SIGNAL_LOOKBACK + _ATR_PERIOD + _OUTCOME_HORIZON + 5` → empty list (safe)
- **Duplicate bars**: `seen_obs_ids` set prevents duplicate `obs_id`
- **Adjusted prices**: `auto_adjust=True` — returns dividend/split adjusted prices ✅

### B. Temporal integrity
- Signal at bar `i` uses `closes[i-20:i]` (prior 20 bars, not current) ✅
- ATR uses `highs/lows/closes[i-14:i+1]` — current bar included ✅ (known at close of day T)
- Outcome uses `highs/lows/closes[i+1:i+6]` — strictly T+1..T+5 ✅
- T+1 cannot use T+0 information ✅ (proven by T019-T023)
- Timezone: yfinance returns timezone-naive UTC timestamps; `str(idx.date())` extracts date safely ✅
- Weekends/holidays: yfinance returns only trading days — no weekend bars ✅
- MultiIndex yfinance: `_df_to_lists()` flattened in BUG-BOOTSTRAP-002 fix ✅

### C. Historical provenance
- `source_type = "HISTORICAL"` on every record ✅
- `validation_partition` ∈ {TRAIN, VALIDATION, OOS, RECENT_OOS} ✅
- `no_lookahead = True` ✅
- `obs_id` format: `KBS_{symbol}_{date}_{uuid8}` — clearly identifies bootstrap origin ✅
- **GAP**: No `bootstrap_version` or `generated_at` timestamp field on OutcomeRecord (minor)

### D. Duplication
- In-memory: `seen_obs_ids` set deduplicates within one `generate_records()` call ✅
- Cross-session: `bootstrap_state.json` prevents re-run within 30 days ✅
- `load_bootstrap_records()` deduplicates by `obs_id` against existing `_outcomes` ✅
- **BUT**: Records are only in-memory singleton. Container restart destroys them.
- **Bootstrap is NOT idempotent across restarts** — records are regenerated every restart, then injected into a fresh singleton, but KDA never reads them.

### E. Historical record quality
Records were verified to contain losses (STOP_HIT), wins (TARGET_HIT), and a mix of regimes. No survivorship bias because:
- ATR stop is 1.5×ATR — not a trivially easy stop
- 5-day horizon is realistic
- T035 and T036 confirm recency decay correctly penalizes old records
