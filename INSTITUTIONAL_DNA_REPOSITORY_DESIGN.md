**Date:** 2026-08-04

## 1. Purpose

The Institutional DNA Repository (IDR) is the permanent persistence layer
for all institutional DNA knowledge generated by the MLS (Market Learning System).

It is the **single source of truth** for:
- Winner DNA, Loser DNA, Neutral DNA
- Consensus DNA
- Contextual DNA (via CDS scores)
- DNA evolution history
- DNA lifecycle transitions
- DNA evidence
- DNA market context snapshots

The IDR stores, versions, and provides read access to DNA records.
It does **not** discover, score, or trade.

---

## 2. Core Principles

### 2.1 Never Overwrite

Every change to a DNA record creates a **new version**. Previous versions
are never modified. The complete history of every DNA record is always
accessible.

### 2.2 Complete Audit Trail

Every write operation (save, update, retire) is logged to `audit_log`
with: operation, DNA id, version before/after, operator, study_id, reason,
and timestamp. Every confidence change can be explained.

### 2.3 Thread Safety

- SQLite WAL journal mode: multiple concurrent readers, one writer
- Python `RLock`: write serialisation at the Python level
- Per-call connections: no cross-thread connection sharing
- Atomic transactions: all writes are wrapped in `BEGIN IMMEDIATE`

### 2.4 Reproducibility

Every DNA record carries: `study_id`, `source`, `created_at`, `updated_at`.
Combined with the `audit_log` and `dna_evidence` tables, any historical
DNA state can be fully reconstructed.

## 6. DNA Lifecycle

The IDR supports the full MLS DNA lifecycle:

```
DISCOVERED
    ↓
REPLICATED
    ↓
VERIFIED
    ↓
INSTITUTIONAL
    ↓
WEAKENING
    ↓
DRIFTING
    ↓
RETIRED
```

Each transition is recorded as a new version with `operation = "UPDATED"`.
Retirement is recorded with `operation = "RETIRED"`.
No lifecycle state is ever deleted.

---

## 7. Versioning

Every DNA record has a `(id, version)` primary key.

- `save()` on an unknown id → version 1 (`operation = "CREATED"`)
- `save()` on a known id → next version (`operation = "UPDATED"`)
- `update()` on a known id → next version (`operation = "UPDATED"`)
- `retire()` on a known id → next version with lifecycle=RETIRED (`operation = "RETIRED"`)
- `get()` → always returns the latest version (`is_current = 1`)
- `get_version(id, n)` → returns any specific version

The `is_current` flag is 1 on the latest version, 0 on all previous versions.

## 8. Knowledge Consumers (Read Access)

The following components can read from the IDR without any dependency
on the MLS runtime:

| Consumer | What they need |
|---|---|
| PMCIEngine | `get()` current ConsensusDNA state |
| CDSEngine | `list_active()` for library evaluation |
| KnowledgeProvider | `history()` for trend synthesis |
| Replay System | `get_version()` for historical states |
| Research Studies | `evidence()` for statistical evidence |
| Scientific Director | `audit_log()` for governance review |
| ResearchCoordinator | `statistics()` for knowledge inventory |
| MarketLearningCoordinator | All methods for lifecycle management |

## 9. Future Migration Path

The IDR is designed for migration:

1. `schema_version` table tracks the current schema version
2. Adding a column: `ALTER TABLE dna ADD COLUMN new_field TYPE DEFAULT val`
3. Migrating data: SQL `UPDATE` within a transaction
4. Incrementing `schema_version` and logging with description
5. If `idr_backup_on_schema_change = True`, auto-backup before migration

The current schema version is **1**.

## 10. Answering the Final Questions

| Question | Answer |
|---|---|
| Can every DNA ever discovered be reconstructed? | Yes — every version is preserved; `get_version()` returns any historical state |
| Can every confidence change be explained? | Yes — `audit_log()` records operator, reason, study, and timestamp for every change |
| Can PMCI obtain institutional DNA without runtime dependencies? | Yes — `IDRRepository.list_active()` requires only SQLite, not any MLS engine |
| Can Scientific Director query any historical DNA state? | Yes — `get_version(id, n)` + `audit_log(id)` reconstructs complete history |
| Can replay reproduce historical DNA versions? | Yes — `get_version(id, n)` returns the exact state of any DNA at any version |
