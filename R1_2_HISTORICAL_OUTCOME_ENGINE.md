# R1.2 — Historical Outcome Engine

**Status:** Implemented  
**File Modified:** `simulation_replay/replay_engine.py` (only)  
**Date:** 2026-08

---

## 1. Root Cause

Replay learning labels were generated by an MD5 hash seeded on `(date, symbol)`:

```python
seed_hex = hashlib.md5(f"{day_data.date}:{symbol}".encode()).hexdigest()[:8]
win      = (int(seed_hex, 16) % 100) < 55   # 55 % win rate
exit_price = target if win else sl
```

This hash has no relationship to whether the price actually reached the target or stop loss on that historical day. The `day_high` and `day_low` for each symbol were already loaded from yfinance and present in `day_data.stock_watchlist` — but were never consulted for outcome resolution.

The same simulation was also used in the `executed_rows` path via `_sim_pnl()`, so the replay report metrics were equally fictitious.

## 2. Implementation Summary

**Three changes, one file (`simulation_replay/replay_engine.py`):**

### New helper: `_resolve_historical_outcome()`

```python
def _resolve_historical_outcome(
    entry, sl, target, direction, day_high, day_low, eod_close
) -> tuple[float, str]:
```

Implements the price-based resolution logic. Returns `(exit_price, close_reason)`.

### `_close_replay_positions_with_outcomes()` — learning path

- Builds `_ohlc` dict from `day_data.stock_watchlist` (`day_high`, `day_low`, `ltp`)
- Calls `_resolve_historical_outcome()` per position instead of MD5 hash
- Positions where `day_high == 0 and day_low == 0` (no historical data) receive `ORPHAN_CLOSE` and are excluded from `_current_day_trades` → excluded from all learning

### `run_replay_day()` `executed_rows` loop — report path

- `hl_lookup` extended from `(high, low)` to `(high, low, close)` tuples
- `_sim_pnl()` call replaced with `_resolve_historical_outcome()` + direction-aware PnL
- Report metrics now reflect real historical outcomes

`_sim_pnl()` remains in the file (used in comments in `fragility_test.py`) but is no longer called from either the learning or report paths.

## 3. Historical Resolution Logic

```
BUY / LONG:
  day_low  <= stop_loss    →  STOP HIT  (exit at stop_loss,  reason="close_sl")
  day_high >= target       →  TARGET HIT (exit at target,    reason="close_target")
  otherwise                →  EOD EXIT  (exit at ltp/close,  reason="eod_close")

SELL / SHORT:
  day_high >= stop_loss    →  STOP HIT  (exit at stop_loss,  reason="close_sl")
  day_low  <= target       →  TARGET HIT (exit at target,    reason="close_target")
  otherwise                →  EOD EXIT  (exit at ltp/close,  reason="eod_close")

Ambiguous candle (both SL and target within day range):
  → Stop loss assumed first (conservative — avoids overstating wins)

No historical data (day_high == 0 and day_low == 0):
  → ORPHAN_CLOSE at entry — excluded from learning
```

### Why SL has priority over target on ambiguous candles

When daily OHLCV is the only granularity available (no tick or intraday bar data), we cannot know the sequence of intraday price moves. The conservative assumption (SL hit first) avoids overstating win rate and aligns with standard daily-bar backtesting convention.

## 4. Validation Results

Expected log output per day after running `python simulation_replay/run_replay.py`:

```
[ReplayOrchestrator] EOD close: N position(s) with historical outcomes.
[ReplayOrchestrator] EOD learning: N trade(s).
[ReplayIntegrity]    Day D PASS — closed=N fed=N labels=N patterns=N
```

Three outcome types should now appear in `data/paper_trades.csv`:
- `close_sl`     — stop loss hit
- `close_target` — target hit  
- `eod_close`    — neither hit, EOD exit at closing price

`forward_return` values in `data/ede_feature_db.json` will reflect actual price movement:
- Positive for target hits and profitable EOD exits
- Negative for stop-loss hits and losing EOD exits
- No longer uniformly tied to 55% win rate

## 6. Remaining Scientific Risks

| Risk | Severity | Ticket |
|---|---|---|
| **Survivorship bias** — `NSE_STOCKS` in `historical_loader.py` is 33 hardcoded 2026 constituents applied to all historical dates | Medium | R1.3 |
| **Same-day OHLCV leakage** — today's `day_high`/`day_low` are visible to the morning-cycle scanner before the trading session closes. The scanner sees today's final close when deciding entry levels. | Low | R1.4 |
| **Ambiguous candle conservative bias** — using daily bars means any day where both SL and target are inside the range gets assigned a loss. In reality ~50% of these would be wins. This slightly understates true win rate. | Low | Accepted — standard daily-bar convention; mitigated by using EOD close when neither is hit |
| **MetaModel cross-day accumulation** — k-NN MetaLearning accumulates features across replay days without a day boundary reset | Medium | R1.5 |
| **EDE symbol universe gap** — `FeatureExtractor.SYMBOL_UNIVERSE` is 20 fixed symbols; equity scanner trades from 33 stocks. Symbols outside SYMBOL_UNIVERSE have no feature rows to enrich even with correct historical outcomes. | Medium | R1.6 |
